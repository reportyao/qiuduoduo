# 「解球」v2.0 · AI 原生重构设计文档

| 项目 | 内容 |
|---|---|
| 产品名 | 解球（暂定） |
| 版本 | v2.0（AI 原生重构） |
| 日期 | 2026-11-01 |
| 取代 | v1.0 |
| 核心变更 | 从"功能型 App"重构为"判决流助理" |

---

## 1. 为什么重构

v1.0 的问题不是功能不够，是**底层假设错了**。

v1.0 假设：用户会打开 App、浏览内容、做出选择。
这个假设属于移动互联网时代。

真实情况是：初级用户每天只愿意给这件事 **30 秒**。他不会浏览，不会筛选，不会研究。他只想有人替他想好了。

**所以产品不该是一个"应用"，该是一个"每天早上对你说一句话的人"。**

---

## 2. AI 原生的定义

### 2.1 三个层次

| 层次 | 特征 | 结论 |
|---|---|---|
| **L1 套壳** | 传统 App + 悬浮聊天按钮 | 假 AI 化，用户问三句就流失 |
| **L2 增强** | AI 生成内容，界面仍是列表/详情/导航 | 半 AI 化，v1.0 属于此层 |
| **L3 原生** | 无导航、助理主动、用户只做反应 | 目标 |

### 2.2 L3 自检清单

产品发布前逐条自查，任一不满足即未达标：

- [ ] 用户打开后第一件事不是点击或打字
- [ ] 产品会主动说话，不只等被问
- [ ] 所有操作能用自然语言一句话完成
- [ ] 没有设置页、没有会员中心、没有"我的"
- [ ] 助理记得用户说过的话、亏过的钱
- [ ] 助理在没把握时敢说"今晚别买"

### 2.3 两个反直觉推论

**推论一：功能会被替代，判断不会。**
功能的竞品是另一个功能；判断的竞品是"用户自己花三小时"。卖的是省下的时间和犹豫。

**推论二：最好的 AI 产品，用户不需要打开它。**
传统 KPI 是使用时长；AI 产品的正确 KPI 是决策完成率。**用完就走才是成功。**

## 3. 核心转变对照

| 维度 | 传统移动互联网 | 本产品（AI 原生） |
|---|---|---|
| 入口 | 首页 + 导航 + Tab | 一条流 |
| 谁先开口 | 用户 | 助理 |
| 产品单位 | 页面 / 功能 | 一次判断 |
| 用户动作 | 浏览、筛选、点击 | 同意 / 追问 / 反对 |
| 配置方式 | 设置页、引导页 | 说一句话 |
| 价值主张 | 帮你找到内容 | 替你想好了 |
| 留存机制 | 打卡、积分、签到 | 关系、记忆、它记得你亏过 |
| 付费点 | 解锁功能 | 获得权限 |
| 失败处理 | 空状态、无结果 | 承认错，并归因 |
| 成功定义 | 用得更久 | 决策更快、更少后悔 |

## 4. 信息架构：判决流

### 4.1 唯一界面

全产品只有一条时间倒序的流。**无 Tab、无菜单、无"我的"、无设置页。**

### 4.2 流的构成

流里只有五类消息：

| 类型 | 触发 | 频率上限 |
|---|---|---|
| **主推判决** | 每日 19:00，或赛前结论变化 | 1 条/日 |
| **避雷榜** | 每日 12:30 | 1 条/日 |
| **预算提醒** | 达预算 80% / 100%、追损、深夜下单 | 触发式，1 条/日 |
| **赛后复盘** | 次日 10:00 | 1 条/日 |
| **对话回复** | 用户主动提问 | 不限 |

**每日固定推送 ≤ 2 条，总推送 ≤ 4 条。** 超过即视为骚扰，用户关闭通知后产品即死亡。

### 4.3 流的视觉结构

```

  [ 买了 ]  [ 为什么 ]  [ 不同意 ]
──────────────────────────────────
今天 12:30
🚫 这 3 场别碰
  利物浦：阵容没定，别急
  拜仁：热得过头了

```

### 4.4 判决卡规格

## 5. 三个交互原语

全产品只有三个动作，不允许增加。

### 5.1 买了

| 项 | 规格 |
|---|---|
| 作用 | 记录真实行为，写入票单，开始跟踪 CLV |
| 后续 | 赛后自动结算；未结算前可撤回 |
| 数据价值 | **唯一的行为数据来源**，用于学习偏好与后续个性化 |
| 反馈 | 轻提示"记下了。赛后我告诉你对不对。" |

### 5.2 为什么（渐进式披露）

三层，逐层展开：

| 层 | 内容 | 面向 |
|---|---|---|
| **L1 一句话** | 卡片上已有的理由 | 所有人 |
| **L2 三个关键变量** | 阵容差、定价偏差、赛程动机 | 好奇的用户 |
| **L3 完整证据链** | 赔率快照、模型概率与区间、会审记录、封存哈希 | 进阶用户 / 质疑者 |

**默认只展开 L1。点一次展开 L2，再点展开 L3。**
实测数据显示，如果 L2 点开率 < 10%，说明初级用户不需要证据，可进一步精简前端。

### 5.3 不同意（产品灵魂）

| 项 | 规格 |
|---|---|
| 用户行为 | 点击"不同意"，可附一句话理由 |
| **系统必须回应** | 不能顺从，不能道歉式退让 |
| 回应结构 | ① 反方最强论证 ② 相似历史先例（含反面样本）③ 若坚持，建议仓位减半 |
| 记录 | 写入偏好记忆，长期统计"用户反对 vs 实际结果" |

回应示例：

```
你说得对，曼城确实有轮换风险。

但数据上：
· 近 3 季曼城欧冠前一轮，净胜球均值 1.8，仅比常规低 0.1
· 官方让球 -1 对应的隐含概率 47%，国际盘 -1.25 对应 52%
· 这个价差在历史上出现 213 次，主队赢盘 112 次（52.6%）

风险确实存在。如果你要买，建议仓位减半。
```

**为什么这个功能最重要：**

1. 建立专业感——顺从的产品没有权威
2. 收集偏好数据——用户反对的场次类型，就是他不信任的领域
3. 降低错误仓位——用户坚持时，至少仓位减半
4. 制造记忆点——用户会记住"那个跟我吵的 AI"

## 6. 人格与语气

### 6.1 人格定位

> 一个懂行的朋友。不是客服，不是专家，不是导师。

| 特质 | 表现 |
|---|---|
| 短句 | 一句话说清，不堆形容词 |
| 有立场 | 敢说"别买""今晚没有值得买的" |
| 认错直接 | 错了就说错了，但会区分"信息不足"和"判断错" |
| 不管教 | 不说道理，只陈述事实 |
| 有记忆 | 会提起"你上次说的" |

### 6.2 语气对照

| 场景 | 好 | 坏 |
|---|---|---|
| 推荐 | "今晚 47 场，我只挑出这 1 场" | "经过 AI 深度分析，为您精选以下赛事" |
| 劝阻 | "这场谁都可能赢，别碰" | "本场比赛存在较大不确定性，建议谨慎" |
| 认错 | "昨晚那场，我错了" | "由于不可抗力因素导致预测偏差" |
| 拒绝 | "今晚没有值得买的" | "今日暂无推荐，敬请期待" |
| 提醒 | "超了你说的 100。今晚到此为止吧" | "您已超出预设预算，请注意理性消费" |

### 6.3 禁用词

稳赚、必中、包赔、稳胆、内部消息、杀庄、跟单、一夜暴富、精准预测、命中率 90%

### 6.4 固定声明（首次打开时出现一次，之后不重复）

> 我不保证每场都对。但每一场都赛前锁定、赛后公开。

## 7. 记忆系统

### 7.1 记忆类型

| 类型 | 示例 | 来源 |
|---|---|---|
| **预算** | 每周 100 元 | 用户口述 |
| **偏好** | 不推德甲、只看单关 | 用户口述 / 行为推断 |
| **历史** | 上周亏 200、连败 3 场 | 系统记录 |
| **承诺** | "我说过只买 50" | 用户口述 + 系统引用 |
| **态度** | 对某类判决反复反对 | 行为统计 |

### 7.2 数据模型

```sql
CREATE TABLE memories (
  memory_id   BIGSERIAL PRIMARY KEY,
  user_id     TEXT NOT NULL,
  kind        TEXT NOT NULL,       -- budget / preference / commitment / attitude
  key         TEXT NOT NULL,
  value       JSONB NOT NULL,
  confidence  NUMERIC,             -- 口述 1.0，推断 0.6
  source      TEXT,                -- user_said / inferred / system
  created_at  TIMESTAMPTZ DEFAULT now(),
  updated_at  TIMESTAMPTZ,
  deleted_at  TIMESTAMPTZ
);
```

### 7.3 记忆规则

1. **必须可见可改**：长按任意消息 → "它记得我什么" → 列表，可删除
2. **口述优先于推断**：用户明确说过的不被行为推断覆盖
3. **过期清理**：推断类记忆 90 天未强化则衰减
4. **不得用于恐吓**：不能拿用户的亏损记忆做营销

### 7.4 记忆的两种用法

**用得好的例子：**
> "上次你说少推串关，今天这单是单关。"

**用错了的例子：**
> "你已经连续亏损 5 次了，要不要试试我们的高级会员？"

第二种会瞬间毁掉信任。

## 8. 冷启动流程

### 8.1 首次打开（不做引导页）

```
今晚 47 场，我挑出 1 场。

先说清楚：我不保证每场都对，
但每一场都赛前锁定、赛后公开。

[ 看这场 ]
```

### 8.2 第一次交互后

```
你平时一次买多少？我记一下，免得劝不住你。

[ 20 以下 ]  [ 20–50 ]  [ 50–100 ]  [ 100 以上 ]
```

**只问一个问题。** 不问年龄、不问偏好、不问联赛。

### 8.3 注册时机

- 查看第一场判决**不需要注册**
- 点"买了"或"为什么 L3"时才触发注册
- 付费墙在用户连续 3 天打开后才出现

### 8.4 冷启动漏斗

```
打开 100%
  ↓ 看到判决
看判决 95%
  ↓ 点"为什么"
看理由 40%（预期）
  ↓ 点"买了"
采纳 15%（预期，这是北极星）
  ↓ 第 3 天仍打开
留存 35%
  ↓ 付费
付费 5–8%
```

## 9. 多模态入口

| 入口 | 用户说/做 | 系统行为 |
|---|---|---|
| **文字** | "今晚买啥" | 返回当日判决 |
| **语音** | "今晚有啥" | 同上，语音回复 |
| **截图** | 群里别人的推荐 | "这个靠谱吗" → 给出独立判断，指出对方推荐的问题 |
| **拍照** | 彩票照片 | 自动记账，更新预算 |
| **转发** | 判决卡 | 生成分享图，带二维码 |

**截图鉴别是我最看好的传播功能。** 用户在群里看到别人荐彩，截图发给你，你给独立判断——这既建立了权威，又天然产生分享。

## 10. 推送节制规则（硬性）

| 规则 | 数值 |
|---|---|
| 每日固定推送 | ≤ 2 条 |
| 每日总推送 | ≤ 4 条 |
| 连续 3 日未打开 | 停止推送 1 天，改为静默 |
| 单条消息长度 | ≤ 80 字（除判决卡） |
| 深夜时段（23:30–08:00） | 仅预算提醒可发 |
| 用户关闭通知后 | 不得用其他渠道补推 |

**"主动"的前提是克制。** 推送超量 = 用户关闭通知 = 产品死亡。

## 11. 指标重构

### 11.1 北极星

**每周被采纳的判决数（Weekly Adopted Verdicts, WAV）**

定义：用户点击"买了"且赛后确认存在的判决数。

为什么选它：
- 直接对应真实价值（用户真的去买了）
- 不可伪造
- 比 DAU 更能反映产品是否被信任

### 11.2 指标表

| 类别 | 指标 | MVP 目标 |
|---|---|---|
| 北极星 | 周被采纳判决数 | 人均 ≥ 1.5 |
| 效率 | 打开到采纳耗时 | < 60 秒 |
| 效率 | 从"为什么"到采纳转化 | ≥ 35% |
| 信任 | L2 证据展开率 | 观察值，不作目标 |
| 信任 | "不同意"后 3 日内回访率 | ≥ 60% |
| 关系 | 平均记忆条数 | ≥ 4 |
| 关系 | 连续采纳周数 | ≥ 2 |
| 留存 | D1 / D7 / D30 | 45% / 22% / 10% |
| 变现 | 免费→付费 | ≥ 5% |
| 质量 | 月 CLV | > +1% |
| 质量 | 避雷准确率 | 高于均值 10pp |
| 反指标 | 日均推送数 | > 4 即预警 |
| 反指标 | 用户关闭通知率 | > 15% 即预警 |

### 11.3 废弃指标

- 使用时长：AI 产品越短越好
- 页面浏览量：没有页面了
- DAU/MAU：改为 WAV

## 13. 一周验证方案（Wizard of Oz）

### 13.1 目标

在写任何前端代码之前，验证三个假设：

| # | 假设 | 判定方法 |
|---|---|---|
| H1 | 初级用户要的是结论，不是数据 | "为什么"点开率 |
| H2 | 一条流能留住人 | 次日打开率 |
| H3 | 用户真的会照着买 | "我买了"的自报比例 |

### 13.2 执行

**第 1–2 天：搭环境**
- 建微信群或服务号
- 用现成模型 + 手工整理数据（5 大联赛够用）
- 不做任何前端

**第 3–7 天：每天跑一轮**

| 时间 | 动作 |
|---|---|
| 12:30 | 发避雷榜（3 条，每条一句话） |
| 19:00 | 发主推（1 场，判决卡文案） |
| 22:00 | 人工收集反馈："今天这场你怎么看" |

**每天只记录四件事：**
1. 有多少人回复/点开
2. 有多少人问"为什么"
3. 有多少人说"我买了"
4. 第二天还在的人有几个

**第 8 天：判定**

| 结果 | 结论 |
|---|---|
| "为什么"点开率 < 10% | 证据层大幅精简，v2.0 的 L2/L3 压缩为一层 |
| "为什么"点开率 10–30% | 保持三层设计 |
| "为什么"点开率 > 30% | 证据是刚需，进阶功能提前 |
| "我买了"比例 < 5% | 判断本身不可信，先修模型再谈产品 |
| 次日打开 < 20% | 流的形式有问题，先修内容节奏 |

### 13.3 为什么这一步不能省

三周 MVP 的假设是"我们知道用户要什么"。
一周 Wizard of Oz 的假设是"我们不知道"。

**后者更可能对。**

## 14. 风险

| 风险 | 表现 | 应对 |
|---|---|---|
| **单流信息过载** | 消息太多，用户滑不到重点 | 硬性 4 条上限；主推永远在最上 |
| **过度主动 = 骚扰** | 关闭通知率飙升 | 节制规则（第 10 节） |
| **聊天框留不住人** | 用户不知道问什么 | 主界面不是聊天，是流；聊天是兜底 |
| **记忆出错** | "我什么时候说过" | 记忆可见可改；口述优先 |
| **AI 猜错即失信** | 一次错就卸载 | 归因三分类 + 连败照发 |
| **"有立场"被误解为傲慢** | "不同意"后语气过硬 | 回应结构固定：先承认对方合理处，再给数据 |
| **Wizard of Oz 结论不可靠** | 30 人样本太小 | 只看方向不看精确值；至少 5 天连续观察 |

## 15. 与 v1.0 的差异清单

### 删除

- 5 个功能模块（今日一句话 / 避雷榜 / 懒人串关 / 预算守护 / 复盘）作为独立功能 → 合并为流内消息
- 首页、详情页、战绩墙页面、会员中心、设置页 → 全部取消
- Tab 导航
- 双层语言映射（初级/进阶两套说法）→ 合并为一套，证据藏进"为什么"
- 进阶视图作为独立页面 → 变为"为什么"的 L3

### 新增

- 判决流
- 三个交互原语（买了 / 为什么 / 不同意）
- 记忆系统（含数据模型）
- 记忆可见可改入口
- 多模态入口（语音 / 截图 / 拍照）
- 推送节制规则
