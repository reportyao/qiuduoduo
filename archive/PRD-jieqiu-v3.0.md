## 0. 三版演进

| 版本 | 问题 | 结论 |
|---|---|---|
| v1.0 | 功能堆砌，做了 6 个模块，是 L2 半 AI 化 | 界面太重，初级用户扛不住 |

v3.0 的关键不是加功能，是**把"为什么推荐这场"变成产品本身**。

## 1. 一句话定义

> **每天晚上，把 47 场比赛砍到 1 场。并告诉你砍掉的 46 场死在哪一关。**

### 1.1 刚需在哪

不是"预测"，是"**筛选**"。

| 用户真实处境 | 为什么是刚需 |
|---|---|
| 每天 20–60 场竞彩，看不完 | 时间刚性，必须有人帮他砍 |
| 不知道砍掉哪场 | 判断刚性，砍错比不砍更痛 |
| 砍完不敢买 | 决策刚性，需要一个"就它了"的终点 |
| 买完管不住手 | 纪律刚性 |

**"预测谁赢"是焦虑，"帮我把 47 场砍到 1 场"是需求。**

前者卖的是希望，后者卖的是省下的两个半小时和那份犹豫。

### 1.2 AI 化在哪

| AI 角色 | 传统 App | 本产品 |
|---|---|---|
| **筛选** | 用户自己翻列表 | AI 跑完三道闸，只给结果 |
| **解释** | 无 | 每个淘汰都有理由 |
| **主动** | 等用户打开 | 19:00 主动说话 |
| **记忆** | 用户自己记 | 记得你亏过多少、答应过什么 |
| **拒绝** | 有求必应 | 没把握就说"今晚别买" |

## 2. 核心机制：三道闸

这是整个产品的骨架。**四价对齐是闸门，推荐是闸门之后的唯一出口。**

```
今日全量赛事  47 场
      │
      ▼
┌─────────────────────────────────────┐
│ 第一道闸 · 价（成本过滤）             │
│ 官方 SP 去水 → 单场抽水率             │
│ 抽水率 > 12% → 淘汰                   │
│                                     │
│ 砍掉 23 场 → 剩 24 场                │
└──────────────────┬──────────────────┘
                   ▼
┌─────────────────────────────────────┐
│ 第二道闸 · 市（分歧过滤）             │
│ 官方 / Pinnacle / 亚盘 / 模型 四家对齐 │
│ 分歧度 > 阈值 → 淘汰（进避雷榜）       │
│                                     │
│ 砍掉 8 场 → 剩 16 场                 │
└──────────────────┬──────────────────┘
                   ▼
┌─────────────────────────────────────┐
│ 第三道闸 · 模（信息过滤）             │
│ 阵容未确认 / 关键伤停不明 / 动机不明   │
│ 信息完整度 < 阈值 → 淘汰              │
│                                     │
│ 砍掉 6 场 → 剩 10 场                 │
└──────────────────┬──────────────────┘
                   ▼
┌─────────────────────────────────────┐
│ 终审 · 势（时机排序）                 │
│ 模型概率 × 市场公允 × 资金动向        │
│ 综合评分排序                          │
│                                     │
│ 输出：主推 1 场 + 备选 2 场           │
└─────────────────────────────────────┘
```

### 2.1 为什么这个结构成立

| 特点 | 说明 |
|---|---|
| **每一关都不可反驳** | 抽水率是除法，分歧度是标准差，都是数学 |
| **淘汰比推荐更可信** | 说"别买"不需要预测能力，只需要识别 |
| **过程即内容** | "47 场砍到 1 场"本身就是最好的产品文案 |
| **稀缺是真实的** | 不是营销话术，是真的只有 1 场过关 |
| **可解释** | 每个用户都能看到自己关注的场次死在哪一关 |

### 2.2 硬性规则

1. **三关全过才有推荐。** 一关不过就没有，哪怕今天一场都没有。
2. **没有推荐时，明确说"今晚没有"。** 不得降低阈值凑数。
3. **每一关的淘汰场次必须对用户可见**（在"为什么"的 L3 层）。

这条第 3 点是关键——它让"砍掉 46 场"这件事可验证，而不是黑箱。

## 3. 数据资产：四价对齐

四价对齐不是功能，是**唯一的数据资产**。它供给三道闸。

### 3.1 四个维度

| 维度 | 定义 | 数据源 | 服务于 |
|---|---|---|---|
| **价** | 官方给的价格 | 竞彩 SP | 闸一：成本过滤 |
| **市** | 全球市场公允价 | Pinnacle 去水 / Betfair | 闸二：分歧过滤 |
| **模** | 自训练模型的概率 | 自有模型 | 闸二 + 终审 |
| **势** | 价格的演化方向与速度 | 盘口时间序列 | 终审：时机排序 |

> 注：原"四价"里的"亚盘主盘"并入"市"维度——它和 Pinnacle 是同一信息源的两种形态，不是独立维度。

### 3.2 明确不做：错价雷达

**已否决。** 原因：竞彩抽水结构决定了"官方 SP 高于公允赔率"的场次极少，不足以支撑一个核心功能。

**替代方案：成本标签。** 不找机会，只揭示成本——它每场都有、永远正确、不会翻车。

### 3.3 从四价能拆出的四样东西

| 拆出物 | 计算 | 用途 |
|---|---|---|
| **单场抽水率** | `1 − 1/Σ(1/SP_i)` | 闸一过滤 + 成分标签 |
| **分歧度** | 四家概率向量的平均标准差 | 闸二过滤 + 避雷榜 |
| **人气偏差** | 官方去水概率 − Pinnacle 公允概率 | 内容素材（"散户都在压曼城"） |
| **价格演化** | 双源时间序列对齐 | 终审排序 + 时机提示 |

**只有第四项是真壁垒**——它需要 1–3 年的分钟级双源快照。从今天开始采集，一天都不能停。

## 5. 功能详细规格

### 5.1 F1 · 每日判决【P0｜付费】

**定义**：三道闸之后唯一通过的那一场。

**判决卡**

```
┌──────────────────────────────────────┐
│ 今天 19:02                            │
│                                      │
│ ⚖ 今晚 47 场，我只留这 1 场            │
│                                      │
│ 曼城 vs 布莱顿                        │
│ 英超 · 单关 ✓ · 21:55 停售            │
│                                      │
│ 让球主胜（-1）                         │
│                                      │
│ 它过了三关：                           │
│ ✓ 价  抽水 9.2%，今日前 20%            │
│ ✓ 市  四家分歧 2.1pp，很低             │
│ ✓ 模  阵容已确认，模型和市场差 3.8pp    │
│                                      │
│ 一句话：                               │
│ 布莱顿两名中卫缺阵，                   │
│ 官方还没完全反映。                      │
│                                      │
│ [ 买了 ]  [ 为什么 ]  [ 不同意 ]       │
│                                      │
│ 赛前封存 21:25 · 已锁定                │
└──────────────────────────────────────┘
```

**关键设计：卡上直接展示"过了三关"。**
这是推荐的可信依据，比任何"AI 看好度"都强——因为三关是用户能看懂的三个筛子。

**时间门控（付费设计）**

| 用户 | 可见时间 | 说明 |
|---|---|---|
| 付费 | 每日 12:30 | 提前 6.5 小时，有实际信息优势 |
| 免费 | 赛前 2 小时 | 能看到，但错过最优 SP |

**这是本产品唯一"诚实"的付费墙**——早看到真的有价值，不是制造焦虑。

**验收标准**

| 指标 | 目标 |
|---|---|
| 推送打开率 | ≥ 15% |
| 采纳率（点"买了"） | ≥ 15% |
| 三关信息点击率 | ≥ 25% |
| 无推荐日占比 | ≤ 20%（超过说明阈值太严） |

### 5.2 F2 · 成分标签【P0｜免费】

**定义**：任意一场比赛的成本透明卡。免费开放，不设门槛。

**这是产品的信任地基。** 它永远正确，永远不会翻车，用户拿计算器就能验证。

```
┌────────────────────────────────────┐
│  这一注的成本                        │
│  曼城 vs 布莱顿 · 让球主胜            │
├────────────────────────────────────┤
│  官方定价抽水      9.2%              │
│  四家分歧度        低  ●○○           │
│  散户情绪          偏主队 ↑          │
│  ─────────────────────────────      │
│  每 100 元的期望回报   −9.2 元        │
│  ─────────────────────────────      │
│  今日 47 场里，这场的水排第 9 浅      │
└────────────────────────────────────┘
```

**正向表达（重要）**

不要说"你亏 9%"，要说：

> 你本周预算 100 元。
> 随便买：平均抽水 11%，约能玩 9 注
> 挑着买：抽水最低的 5 场，平均 7%，约能玩 14 注

**同一个事实，用户感受完全不同。**

**入口**
- 判决卡里点"为什么" → L2 层
- 任意比赛搜索
- 每日"水位榜"

**验收标准**

| 指标 | 目标 |
|---|---|
| 判决卡 → 成分标签点击率 | ≥ 30% |
| 用户回访查看其他场次比例 | ≥ 20% |

---

### 5.3 F3 · 避雷榜【P0｜免费】

**定义**：被三道闸淘汰的场次中，风险最高的 3–5 场。

**与逐场淘汰的区别**：避雷榜只展示"用户最可能踩坑"的那几场——通常是被公众资金推热的热门场。

```
🚫 这 3 场别碰

利物浦 vs 埃弗顿
  水太深，抽水 13.4%（今日最深）

拜仁 vs 弗赖堡
  四家分歧 7.8pp，这场谁都可能赢

皇马 vs 塞维利亚
  阵容没定，别急
```

**为什么避雷榜比推荐更值钱**

| | 推荐 | 避雷 |
|---|---|---|
| 是否需要预测 | 需要 | **不需要** |
| 准确率 | 55% 左右 | **70%+** |
| 翻车代价 | 高（用户亏钱怪你） | 低（用户没买，最多少赚） |
| 用户感激度 | 中 | **高**（避坑是确定的） |

**验收标准**

| 指标 | 目标 |
|---|---|
| 避雷场次实际亏损比例 | 高于平均 ≥ 10pp |
| 展开率 | ≥ 35% |
| "有用"反馈 | ≥ 60% |

### 5.4 F4 · 预算守护【P0｜免费】

**定义**：用户设周预算，系统跟踪并在超支、追损、深夜下单时拦截。

| 功能 | 规则 |
|---|---|
| 预算设置 | 首次对话时问一次，之后可随时改 |
| 投入记录 | 点"买了"自动记；支持截图/拍照 |
| 超支提醒 | 80% / 100% 各一次 |
| 追损拦截 | 同晚连续 2 单亏损后再买，弹冷静提示 |
| 深夜提醒 | 23:30 后提示明天再看 |

**文案原则**：不说道教，只陈述事实。

> 你今天买了 3 单，共 120 元。
> 超了你说的 100。今晚到此为止吧。

**验收标准**

| 指标 | 目标 |
|---|---|
| 预算设置率（7 日内） | ≥ 50% |
| 开启守护用户周均投入 | 下降 ≥ 20% |
| 追损提示后二次下单率 | 下降 ≥ 30% |

---

### 5.5 F5 · 赛后归因【P0｜免费】

**定义**：次日推送复盘，赢输都发，且必须给出归因类型。

**归因三分类**

| 类型 | 判定条件 | 用户感知 |
|---|---|---|
| **信息不足** | 赛前有未获取的关键信息 | 可原谅 |
| **模型偏差** | 无新信息，判断本身有问题 | 需改进 |
| **随机波动** | 判断正确，结果落在少数侧 | 正常 |

**示例**

> 昨晚那场，我错了。
> 曼城 1-1。
> 原因是客队临时换门将，这信息我赛前没拿到——
> 属于"信息不足"，不是判断错。
>
> 这个月第 3 次信息不足了。我已经把门将变动的抓取加进去了。

**为什么这个功能是留存核心**

用户流失不是因为亏钱，是因为"我是不是傻"。归因把"运气差"和"判断错"分开，他就有理由留下。

**验收标准**

| 指标 | 目标 |
|---|---|
| 连败期（≥3 连败）7 日留存 | 高于对照组 ≥ 15pp |
| 复盘推送打开率 | ≥ 20% |

---

### 5.6 F6 · 记忆系统【P0｜底层】

**记忆类型**

| 类型 | 示例 | 来源 |
|---|---|---|
| 预算 | 每周 100 元 | 口述 |
| 偏好 | 不推德甲、只看单关 | 口述 / 推断 |
| 历史 | 上周亏 200、连败 3 场 | 系统 |
| 承诺 | "我说过只买 50" | 口述 + 引用 |
| 态度 | 对某类判决反复反对 | 行为统计 |

**规则**

1. 必须可见可改（长按消息 → "它记得我什么"）
2. 口述优先于推断
3. 推断类记忆 90 天未强化则衰减
4. **不得用于恐吓**——禁止"你亏了 5 次，升级会员吧"

---

### 5.7 F7 · 备选推荐【P1｜付费】

通过三关但排名 2–3 的场次。用于：
- 用户不接受主推时给替代
- 做 2 串 1 组合

**必须标注**："这两场不如主推，只是为了让你有选择。"

---

### 5.8 F8 · 进阶视图【P1｜付费】

"为什么"的 L3 层：四价明细、概率区间、模型分歧、封存哈希、淘汰场次全表。

**面向 8% 的进阶用户，不做独立页面。**

## 6. AI 原生的五个角色

### 6.1 自检清单（发布前逐条判定）

- [ ] 打开后第一件事不是点击或打字
- [ ] 产品会主动说话
- [ ] 所有操作能用一句话完成
- [ ] 没有设置页、会员中心、"我的"
- [ ] 助理记得你说过的话
- [ ] 助理敢说"今晚别买"

### 6.2 交互原语：只有三个

| 动作 | 系统必须做的 |
|---|---|
| **买了** | 记账、跟踪 CLV、学习偏好 |
| **为什么** | 三层展开：一句话 → 三关信息 → 完整证据链 |
| **不同意** | **不得顺从**：先承认合理处 → 给数据 → 建议仓位减半 |

**"不同意"的回应示例**

> 你说得对，曼城确实有轮换风险。
>
> 但：
> · 近 3 季曼城欧冠前一轮，净胜球均值 1.8，只比常规低 0.1
> · 这场抽水 9.2%，是今日第 9 浅
> · 四家分歧只有 2.1pp
>
> 风险存在。如果你要买，建议仓位减半。

### 6.3 判决流

全产品只有一条时间倒序的流，无 Tab、无菜单、无设置页。

| 消息类型 | 触发 | 上限 |
|---|---|---|
| 主推判决 | 12:30（付费）/ 赛前 2h（免费） | 1 条/日 |
| 避雷榜 | 12:30 | 1 条/日 |
| 预算提醒 | 触发式 | 1 条/日 |
| 赛后归因 | 次日 10:00 | 1 条/日 |

**每日总推送 ≤ 4 条。超过即视为骚扰。**

### 6.4 人格

> 一个懂行的朋友。不是客服，不是专家。

| 场景 | 好 | 坏 |
|---|---|---|
| 推荐 | "今晚 47 场，我只留这 1 场" | "AI 深度分析为您精选" |
| 劝阻 | "水太深，别碰" | "本场存在较大不确定性" |
| 认错 | "昨晚那场，我错了" | "由于不可抗力因素" |
| 拒绝 | "今晚没有值得买的" | "今日暂无推荐" |
| 提醒 | "超了你说的 100。到此为止吧" | "请注意理性消费" |

**禁用词**：稳赚、必中、包赔、稳胆、内部消息、杀庄、跟单、精准预测、命中率 90%

## 7. 模型策略

### 7.1 自训练模型的唯一价值：分歧

> **模型和市场一致时，它什么也没说。模型的唯一价值是"和市场的分歧"。**

所以模型的产品化形态不是"展示概率"，而是：

```
我不同意市场。
市场给 52%，我的模型给 57%，差 5pp。
理由是：两名中卫缺阵的影响，市场还没完全定价。
```

**如果模型永远跟随市场，它没有存在意义。**

### 7.2 技术选型

| 环节 | 方案 | 理由 |
|---|---|---|
| 强度估计 | xG-based，时间衰减 180 天 | 方差比进球低 60% |
| 比分分布 | Dixon-Coles（ρ ≈ −0.06） | 20 行代码，可解释 |
| 市场概率 | Shin 法去水 | 比简单归一化更准 |
| 融合 | logit 空间加权 | 概率空间线性混合会失真 |
| 校准 | isotonic，out-of-fold，分联赛 | 未校准比没模型更危险 |
| 语言模型 | 只做抽取和叙述，**不产生数字** | 数字必须来自数据库 |

### 7.3 强制纪律

- 禁止用开售 SP 做回测，必须用收盘价
- 禁止用当季数据训练当季
- 禁止使用赛后确认的阵容
- 回测必须 walk-forward
- LLM 输出必须过数字白名单校验

### 7.4 不做的事

- **不做领域继续预训练**（语料不够，知识过期快）
- **不端到端训预测模型**（毁掉可审计性）
- **不做错价雷达**（已否决，抽水结构不允许）

## 8. 指标体系

### 8.1 北极星

**每周被采纳的判决数（WAV）**

定义：用户点"买了"且赛后确认的判决数。

为什么选它：直接对应真实价值，不可伪造，比 DAU 更能反映信任。

### 8.2 指标表

| 信任 | 成分标签查看率 | ≥ 30% |
| 关系 | 平均记忆条数 | ≥ 4 |

| 质量 | 避雷准确率 | 高于均值 10pp |

## 9. 验证计划

### 9.1 第一优先：三个数（2 周，不写前端）

用 3 个月历史数据算：

| # | 观察 | 通过 → 决策 | 不通过 → 决策 |
|---|---|---|---|
| **1** | 单场返还率真实分布 | 集中在 88–95%，成本故事成立 | 接近 97%，砍掉成分标签 |
| **2** | 各场次抽水离散程度 | 极差 > 5pp，"挑水浅"成立 | 极差 < 2pp，闸一失效，重设 |
| **3** | 官方去水 vs Pinnacle 平均差 | > 3pp，人气偏差可做 | < 1pp，官方定价很准，只做成本 |

**第 2 条最关键**：如果所有场次抽水差不多，"47 砍到 1"的第一道闸就废了，得换成别的过滤条件。

### 9.2 第二优先：Wizard of Oz（1 周）

不写代码，微信群 + 手工判决跑 7 天，30 人。

只观察四件事：
1. 有多少人回复/点开
2. 有多少人问"为什么"
3. 有多少人说"我买了"
4. 第二天还在的有几个

**判定**

| 结果 | 结论 |
|---|---|
| "为什么"点开 < 10% | 证据层大幅精简 |
| 10–30% | 保持三层 |
| > 30% | 证据是刚需，进阶功能提前 |
| "我买了" < 5% | 判断不可信，先修模型 |
| 次日打开 < 20% | 内容节奏有问题 |

## 11. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| **三个数不通过** | 闸一失效，产品要重设 | W0 先验证，不通过改方案 |
| 模型无 edge | 推荐失去价值 | 转向"纪律 + 成本"定位，不宣称预测 |
| 连败流失 | 核心风险 | 归因三分类 + 连败照发 |
| 无推荐日太多 | 用户体验空 | 阈值可调；空窗日推"水位榜" |
| 用户归因外部化 | 赢了是他，输了怪你 | 明确"不保证每场对"，强调过程 |
| 数据源断供 | 服务中断 | 每源至少一个备份 |
| 推送过量 | 关闭通知，产品死亡 | 硬性 4 条上限 |
| 竞彩规则变更 | 数据失效 | 监控规则页，异常告警 |
