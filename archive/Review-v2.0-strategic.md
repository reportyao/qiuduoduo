## 一、三个改变方案的发现

### 发现 1：国内定位必须手术（最高优先级）

**事实**：微信公众平台 2025 年发布《关于体育违规荐彩内容的治理公告》，判定标准为两条同时命中：
1. 赛事分析缺失（可验证分析占比过小）
2. 暗示高命中率 / 稳赢（"红单""必中""连红""私厨""精准拿捏"等黑话）

同时，新华社等官媒已将 **"AI 荐彩 / 精准预测 / 高胜率算法"** 定性为网络赌球引流的新包装，典型链路是：社交平台发"AI 预测"→引流私域→诱导下载境外 App→资金外流。

**对我们的影响**：

| 现在的定位 | 风险 | 必须改成 |
|---|---|---|
| "AI 预测比赛结果" | **高危**，与官媒点名的引流模式同构 | "竞彩定价分析与决策辅助工具" |
| "AI 好看度 82" | 暗示命中率 | "官方定价抽水 9.2%，今日第 9 浅" |
| "今晚我只留这 1 场" | 边界内（是筛选不是承诺） | 保留，但配"三关"事实依据 |
| "AI 判决" | 暗示预言 | "今日结论" |

**手术后的核心叙事（国内）**：

> 我们不预测谁赢。我们算清楚这一注的成本，帮你少输。

这句话同时解决三件事：合规安全、差异化、和"永远不会翻车"（成本是数学，不是预言）。

**文案禁用词扩展**：红单、必中、连红、私厨、精准拿捏、稳赢、稳胆、内幕、杀庄、跟单（这些是微信公告点名的黑话，出现即判违规）。

**海外不受此限**，仍可用 "AI edge / model confidence"，但同样禁止 "guaranteed"。

### 发现 2：真正的钱在海外 affiliate，不在订阅

**搜索到的行业数据**：

| 模式 | 数值 |
|---|---|
| 体育博彩 RevShare | 20–40% GGR/NGR |
| CPA（首次存款用户） | $50–250，激进地区可达 $500–800 |
| 混合 | €50–200 CPA + 15–40% 尾佣 |

**对比我们的订阅模型**：

| | 中国订阅 | 海外 affiliate |
|---|---|---|
| 单用户价值 | ¥29/月，年 ¥348 | **CPA $100 ≈ ¥720 一次性** |
| 获客成本容忍度 | 极低 | 高 |
| 规模化难度 | 高（付费转化 1–3%） | 中（只需免费用户） |
| 合规风险 | 中 | 高（需牌照地区审查） |

**结论：双轨商业模型。**

| 市场 | 主收入 | 次收入 |
|---|---|---|
| **中国** | 订阅（¥29/¥199）+ 赛季通行证 | ❌ 不能做 affiliate（违法） |
| **海外** | **Affiliate 导流（CPA/RevShare）** | 订阅（$4.99） |

**这解释了为什么全球化不是"顺便做"，而是商业模型的主战场**——海外一个免费用户导流价值 ¥700，国内一个付费用户年价值 ¥348。

**但有一条铁律**：affiliate 只在**持牌合法**的司法辖区做（UK/US 部分州/北欧），且必须显示牌照与 responsible gambling。不做境外赌博引流——那是刑事红线。

### 发现 3：开源复用的量级被严重低估

原 TechSpec 假设自己写 Dixon-Coles、自己写去水、自己写回测、自己写通知、自己写埋点。**对 OPC 这是错的。**

实测可复用项目把工期从 **14 周压到 8 周**：

| 自建项 | 开源替代 | 省时 |
|---|---|---|
| Dixon-Coles 模型 | **penaltyblog**（Cython 加速 250×，含贝叶斯/层级模型） | 2–3 周 |
| 赔率去水 | penaltyblog 内置 + **mberk/shin** | 3 天 |
| 回测框架 | **georgedouzas/sports-betting** | 1–2 周 |
| 数据抓取 | penaltyblog（football-data/FBref/Understat/ClubElo 全内置） | 1 周 |
| 认证系统 | **Supabase Auth** | 1 周 |
| 埋点 + Feature Flag + A/B | **PostHog**（一个替代三个自建） | 1.5 周 |
| 多渠道通知 | **Novu**（自托管，60+ provider） | 1 周 |
| 管理后台 | Supabase Studio / Directus | 1 周 |
| 脚手架 | nineTails / scaffoldo 参考 | 3 天 |

**penaltyblog 特别值得说**：它已经把 Dixon-Coles 写成 Cython、包含贝叶斯层级模型、亚洲让球盘概率计算、以及直接从 football-data.co.uk / FBref / Understat / ClubElo 拉数据。**我们原计划的模型层，它 80% 都写好了。**

## 二、交互：不重构，做「三层收敛 + 六微交互 + 卡片路由」

### 2.1 判断：15 屏对 OPC 太多

| 现状 | 问题 |
|---|---|
| 15 个界面 | 一人维护不动，每加一屏都是长期负担 |
| 4 个助手 | 本质是 4 个入口，用户不会用 |
| 日历 / 模型周报 / 冷门指数 | 都是"M2 再说"的锦上添花 |

**收敛到 3 个界面：**

```
① 流（唯一主界面）      ② 详情（判决/成本二合一）      ③ 设置（我的）
   + 一个抽屉（功能面板）   + 一个弹层（买了确认）        + 一个弹层（语言/合规）
```

外加减到 **2 个助手**（盘口哨兵 + 纪律管家），另两个做成流内消息，不做独立页。

### 2.2 高级感怎么做（成本极低，效果极强）

关键认知：**高级感 = 信息密度 × 克制 × 微交互**，不是功能数量。

| # | 微交互 | 开发量 | 感知效果 |
|---|---|---|---|
| 1 | **流式生成结论**（SSE 逐字出） | 后端 30 行 + 前端 20 行 | ★★★★★ AI 感最强的单一手段 |
| 2 | **哈希指纹可视化**（hash 前 16 位渲染 4×4 点阵，封存时逐点亮） | 纯 CSS + 20 行 JS | ★★★★★ 独一份，别人抄不走 |
| 3 | **数字滚动**（成本数从 0 滚到 9.2%） | 20 行 | ★★★★ |
| 4 | **骨架屏 + 卡片逐条浮现**（stagger 60ms） | CSS | ★★★★ |
| 5 | **数据源实时状态行**（"4 源在线 · 12s 前同步"） | 一行字 | ★★★★ 廉价科技感天花板 |
| 6 | **封存轻音效 + 触觉**（vibrate 10ms，可关） | 10 行 | ★★★ |

**六项合计不到 200 行代码。**

### 2.3 反过来：砍掉哪些"看起来很酷但很贵"的

| 不做 | 原因 |
|---|---|
| 实时 WebSocket 全站 | 轮询 + SSE 够用，运维成本差 10 倍 |
| 自定义图表库 / D3 复杂可视化 | 轻量 SVG 足够 |
| 动效引擎（Framer Motion 全站） | CSS transition 够 |
| Generative UI（A2UI/AG-UI 全量） | 太重，OPC 做不动 |
| 独立 App | PWA 先行，M3 再说 |
| 语音输入 | 用系统输入法的语音键，零开发 |

### 2.4 但有一个"轻量生成式 UI"，值得做

**卡片路由（Controlled Generative UI 极简版）**：

预定义 8 个卡片组件，LLM 只做一件事——**决定该出哪张卡 + 填什么参数**：

```python
# 用户说任何话 → LLM 返回 {"card": "cost_label", "args": {"match_id": "..."}}
CARDS = {
  "verdict":     "今日结论卡",
  "cost_label":  "成分标签卡",
  "water_rank":  "水位榜卡",
  "agent_alert": "哨兵告警卡",
  "budget":      "预算状态卡",
  "ledger":      "账本摘要卡",
  "memory":      "记忆卡",
  "empty":       "无结论/教育卡",
}
```

用户说"曼城这场怎么样" → 返回 `cost_label` 卡；说"我最近亏了多少" → 返回 `ledger` 卡。

**开发量：一个 LLM 分类 prompt + 一个 8 分支渲染器，约 2 天。**
**感知效果：用户觉得"AI 真的懂我在问什么"，而不是吐一段文字。**

这是 OPC 能做的最高性价比"生成式 UI"。

### 2.5 UI 结论

> **不重构，做减法。3 屏 + 6 个微交互 + 卡片路由。**
> 高级感来自"每一屏都极准"，不来自"功能很多"。

## 四、商业模型重构

### 4.1 双轨模型

```
                       ┌─ 中国 ──────────────┐
                       │ 订阅：¥29 / ¥199 月   │
                       │ 赛季通行证：¥199/季   │
                       │ ❌ 无 affiliate       │
                       └──────────────────────┘
  用户 ──┬─────────────┤
         │             └─ 海外 ──────────────┐
         │                │ Affiliate（CPA $50-250）│
         │                │ 订阅：$4.99/月          │
         │                │ B端白标：$99+/月        │
         │                └─────────────────────────┘
         └─ B 端（全球）：白标判决流 + API
```

### 4.2 中国：为什么订阅天花板低，怎么破

| 问题 | 数据 | 解法 |
|---|---|---|
| 付费率低 | 工具类 1–3% | **赛季通行证**（一次性 ¥199，心理门槛低于"订阅"） |
| 月付流失 | 彩票用户是"事件驱动" | 按赛季/大赛周期卖（世界杯、欧洲杯） |
| 客单低 | ¥29 | **高客单社群**：¥999/季的小班陪跑（限 50 人） |
| 不能 affiliate | 违法 | B 端白标（卖给店主/博主，¥1500/月） |

**真实测算**：10 万 MAU × 2.5% × ¥29 ≈ **¥7.25 万/月**。这是 C 端天花板，够活不够大。B 端 10 家 × ¥1500 = ¥1.5 万/月。

### 4.3 海外：affiliate 是主收入

**链路**：

```
免费工具（赔率计算器 / CLV 追踪 / 抽水计算器）
   ↓ SEO / Reddit / Twitter
免费用户（不需注册）
   ↓ 注册看判决
付费订阅 $4.99（次要）
   ↓ 或者：点"去下注" → 联盟链接
Affiliate 收入 $50–250/FTD（主要）
```

**关键设计**：海外版必须有"**去下注**"按钮（跳转持牌博彩商），这是变现命脉。国内版绝对不能有。

**合规前提**：
- 只在持牌辖区（UK/US 部分州/北欧）
- 显示牌照号 + 18+ + BeGambleAware
- 不做"保证盈利"表述
- 部分地区要求 affiliate 注册

### 4.4 定价重构

| 市场 | 方案 | 价格 | 说明 |
|---|---|---|---|
| CN | 免费 | ¥0 | 1 场/日 + 成本标签 + 避雷 |
| CN | 会员 | **¥29/月 或 ¥199/赛季** | 全量 + 时间门控 |
| CN | 专业 | ¥199/月 | 进阶视图 + alpha |
| CN | 社群 | ¥999/季 | 限 50 人，人工陪跑 |
| CN B端 | 白标 | ¥1500/月 | 判决流 + API |
| Global | Free | $0 | 同 CN |
| Global | Pro | **$9.99/月** | 比 $4.99 高，因为海外付费意愿强 |
| Global | Affiliate | — | 主收入 |
| Global B端 | White-label | $299/月 | |

## 五、全球化推广

### 5.1 冷启动三件套（零预算）

| 手段 | 做法 | 预期 |
|---|---|---|
| **免费工具矩阵** | 赔率计算器 / CLV 追踪器 / 抽水计算器 / 亚盘换算，全部免费无注册 | SEO 长尾，月自然流量 5k–20k |
| **公开账本站** | 独立子域，全量战绩 + 校准曲线，可被引用 | 天然外链，专业背书 |
| **Reddit / Twitter** | r/soccerbetting, r/SoccerBettingTips 发**方法论**不发票单 | 精准种子 |

### 5.2 传播设计

**"我们今晚不推"是最好的营销。**

当一个产品敢公开说"今晚 47 场全砍了，没有值得买的"，它的"有"才值钱。做成固定栏目：每周统计"本周砍掉多少场、只推了几场"。

这是唯一一个**竞品无法模仿**的传播点——因为他们靠每天出单赚钱。

### 5.3 SEO 关键词矩阵（英文）

| 类型 | 关键词 | 对应页面 |
|---|---|---|
| 工具型 | value bet calculator, overround calculator, CLV tracker | 免费工具页 |
| 方法型 | how to beat closing line, what is closing line value, asian handicap explained | 内容页 |
| 对比型 | oddsjam alternative, unabated vs | 对比页 |
| 长尾 | premier league betting model, xg prediction model | 联赛页 |

**不要打**："best betting tips""sure wins"（垃圾流量 + 合规风险）。
