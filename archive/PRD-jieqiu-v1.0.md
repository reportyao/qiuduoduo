## 1. 背景与问题定义

### 1.1 市场现状

竞彩足球是中国体育彩票的主要玩法之一，综合返奖率长期在 65%–75% 区间（分玩法、分年份规则调整过）。这意味着无差别随机投注的长期期望为负。

围绕竞彩存在大量"荐彩"内容，但普遍存在三个问题：

1. **只有结论，没有依据**：给出"看好主胜"，无法验证，无法复盘。
2. **选择性公示**：只展示命中的场次，隐藏连败。
3. **无纪律工具**：用户真正的亏损来源是追损和乱串关，但没人管这件事。

### 1.2 用户的核心问题

初级彩民的真实痛点不是"不知道怎么预测"，而是：

- 决策效率低：一场比赛要翻 3–5 个网站，最后靠感觉。
- 害怕踩坑：跟热门然后爆冷，在群里丢面子。
- 缺乏约束：预算失控、追损、深夜下单。
- 输了没有解释：不知道是判断错还是运气差，只能归因于"运气不好"或"AI 不行"。

### 1.3 产品机会

用一套完整的量化引擎（数据 + 统计模型 + 大模型情报抽取），把结论压缩成一句话，同时保留完整的可审计证据链。

**前台极简，后台完整。** 用户只看到一句话，但这句话背后有别人拿不出的证据。

## 2. 产品定位与边界

### 2.1 一句话定位

> 一个每天只用一句话告诉你"今晚买什么、别买什么"的 AI 竞彩助理。

### 2.2 产品边界（合规设计约束）

本产品是**数据分析与信息服务工具**，不是投注平台。以下为硬性边界，不可突破：

| 不做 | 原因 |
|---|---|
| 售彩、代购、代下注 | 未经批准利用互联网销售彩票属违法行为 |
| 合买、代持资金、资金池 | 性质变为非法集资/变相售彩 |
| 按中奖分成、收益承诺 | 构成变相售彩，且收入与用户亏损绑定 |
| 任何"稳赚""必中""包赔"表述 | 违反广告法及彩票相关管理规定 |

**必须做：**

| 要做 | 实现方式 |
|---|---|
| 年龄门槛 | 注册时年满 18 岁确认，未通过不可使用付费功能 |
| 理性购彩提示 | 预算设置页、超支提醒页固定展示 |
| 支付类目 | 走"软件服务/信息技术服务"，不使用"彩票"类目 |
| 内容标注 | 所有推荐页标注"数据分析结果，不构成投注建议" |

> 注：以上为产品存活的前提条件，不是可选项。任何一条被突破，支付通道或应用分发渠道会被直接关闭。

### 2.3 与竞品的差异

| 维度 | 传统荐彩号 | 本产品 |
|---|---|---|
| 输出 | 结论 | 结论 + 一句话理由 + 可审计证据 |
| 战绩 | 只发命中 | 全量公示，含连败 |
| 反面 | 无 | 避雷榜（主动劝阻） |
| 纪律 | 无 | 预算守护 + 追损拦截 |
| 归因 | 无 | 赛后三分类归因（信息/模型/运气） |
| 可验证 | 不可 | 赛前哈希封存，赛后自动结算 |

## 3. 目标用户

### 3.1 用户分层

| 层级 | 占比 | 画像 | 核心诉求 | 付费 |
|---|---|---|---|---|
| **初级玩家（基本盘）** | 90% | 每周 2–3 次，客单 20–100 元，只玩胜平负/让球，大量 2 串 1 | 决策减负、避免踩坑、控制预算 | ¥29/月 |
| 进阶玩家 | 8% | 懂亚盘、看 xG、自己做组合 | 数据效率、概率对照、策略验证 | ¥199/月 |
| B 端（博主/店主/社群主） | 2% | 有流量，需日更内容 | 内容产能、专业背书 | ¥1500+/月 |

### 3.2 初级玩家用户画像（主目标）

**典型用户：小李，28 岁，上班族**

- 每周五、周六晚上买 2–3 单，每次 30–80 元
- 只用手机，在微信里看内容
- 不懂亚盘，不理解"水位""让球半一"这类术语
- 喜欢买 2 串 1，因为"赔率高、看着爽"
- 输了会在当晚再买一单，试图扳回来
- 赢了会截图发群，输了不说话
- 决策时间不超过 1 分钟，不读长文

**他的三个恐惧：**
1. 跟着热门买了然后爆冷，在群里被笑
2. 看到一堆数据但不知道哪个重要
3. 买完就改，改完又错

**产品对他的承诺（对外统一话术）：**

> 每天一句话，告诉你今晚买什么、别买什么、花多少钱。
> 我们不保证每场都对，但每一场都赛前锁定、赛后公开。

### 3.3 非目标用户

- 高资金/职业投注者（合规风险高，不做）
- 未成年人（禁止）
- 寻求"包中""稳赚"的用户（不做这类承诺，主动劝退）

## 5. 功能需求

优先级定义：**P0 = MVP 必须；P1 = MVP 后 1 个月；P2 = 3 个月内；P3 = 视情况**

### 5.1 F1 · 今日一句话【P0】

**描述**
每日固定时间推送当日最有价值的一场比赛的完整结论。这是产品的核心入口和唯一免费的完整推荐。

**触发时间**
- 每日 12:00：次日赛事开盘推送（可选）
- 每日 19:00：当日主推（核心推送）
- 赛前 60 分钟：若首发公布导致结论变化，推送"结论更新"

**内容结构**

```
┌──────────────────────────────────────┐
│ ⚖ 今晚只推这一场                      │
│                                      │
│ 英超 · 曼城 vs 布莱顿                 │
│ 竞彩 #周三012 · 单关 ✓ · 21:55 停售   │
│                                      │
│ 结论：让球主胜（-1）                   │
│ AI 看好度  82  ████████░░             │
│                                      │
│ 为什么：                              │
│ 布莱顿两名主力中卫确认缺阵，           │
│ 官方让球 -1 比国际盘口更划算。         │
│                                      │
│ [ 查看完整分析 ]  [ 加入我的票单 ]     │
│                                      │
│ 赛前封存 21:25 · 哈希 9f3a...c721     │
└──────────────────────────────────────┘
```

**业务规则**
- 每日全量赛事中，仅输出满足 `edge > 2%` 且 `置信度 ≥ B` 的场次，最多 1 场
- 若无满足条件的场次，推送"今晚没有值得买的比赛"，并展示避雷榜
- **不得降低阈值凑数**

**验收标准**
| 指标 | 目标 |
|---|---|
| 推送打开率 | ≥ 15% |
| 打开→点击详情转化 | ≥ 40% |
| 结论生成到推送延迟 | < 5 分钟 |
| 免费用户可见 | 完整（不打码） |

### 5.2 F2 · 避雷榜【P0】

**描述**
每日列出 3–5 场"不建议参与"的比赛，并给出一句话原因。这是本产品最被低估的功能——所有竞品都在喊"买这个"，没人敢说"别买这个"。

**入选规则**（满足任一即入榜，按风险排序）

| 类型 | 判定条件 | 一句话模板 |
|---|---|---|
| 信息不足 | 首发未公布 / 关键球员状态不明 | "阵容还没定，别急" |
| 价值为负 | 官方 SP 隐含概率显著差于公允价 | "这个价买亏了" |
| 高波动 | 双方实力接近且近期状态波动大 | "这场谁都可能赢，别碰" |
| 冷门陷阱 | 热门方 SP 被公众资金压低 | "热得过头了" |

**交互**
- 首屏 F1 卡片下方，折叠展示
- 每条一行：`比赛 · 风险类型 · 一句话原因`
- 支持"我就不信"按钮 → 记录用户逆反行为，用于后续个性化提示

**验收标准**
| 指标 | 目标 |
|---|---|
| 避雷场次实际亏损比例 | 高于全体平均 ≥ 10pp |
| 避雷榜展开率 | ≥ 35% |
| 用户反馈"有用"占比 | ≥ 60% |

**为什么避雷榜不会翻车**
它不预测结果，只识别"高不确定性 + 低价值"的场次。这类场次的判定准确率远高于胜负预测。

### 5.3 F3 · 懒人串关【P0】

**描述**
初级用户大量使用 2 串 1、3 串 1。本功能让用户输入预算和风险偏好，一键生成建议组合。

**输入**
- 预算：默认 ¥50，可调
- 风险偏好：稳（中奖率优先）/ 均衡 / 搏（赔率优先）

**输出**
```
方案 A · 2 串 1 · 稳健
  曼城 让球主胜  ×  利物浦 主胜
  中奖概率 38.2%
  投入 ¥50    最高回报 ¥142
  期望回报 ¥-8.5（串关会放大抽水）

方案 B · 3 串 1 · 搏
  ...
```

**业务规则（重要）**
- **必须明确展示期望值为负**，不得隐藏
- 必须展示"串关每多一关，抽水被放大约 X%"
- 当用户选择 3 串以上时，弹出一次提示："每加一关，中奖概率约降 40%"

**验收标准**
| 指标 | 目标 |
|---|---|
| 生成响应时间 | < 2 秒 |
| 期望值展示完整率 | 100%（不允许省略） |
| 用户选择 3 串以上比例 | 较无提示时下降 ≥ 25% |

### 5.4 F4 · 预算守护【P0】

**描述**
用户设定周预算，系统跟踪实际投入，在超支、追损、深夜下单时提醒。

**功能点**

| 功能 | 规则 |
|---|---|
| 预算设置 | 注册后引导设置周预算（默认 ¥100） |
| 投入记录 | 手动录入（金额 + 场次）；V2 支持截图 OCR |
| 超支提醒 | 达到预算 80% 提醒一次，100% 再提醒一次 |
| 追损拦截 | 同一晚连续 2 单亏损后再下单，弹出冷静提示 |
| 深夜提醒 | 23:30 后下单，提示"明天再看" |
| 每周报告 | 周日推送：本周投入、盈亏、预算达成率 |

**文案原则**
不说道教，只陈述事实。例如：

> "本周已投入 ¥120，超过你设的 ¥100。
> 上周你在超预算后追加的 3 单，全部亏损。"

**验收标准**
| 指标 | 目标 |
|---|---|
| 预算设置率（新用户 7 日内） | ≥ 50% |
| 开启守护用户周均投入变化 | 下降 ≥ 20% |
| 追损提示后的二次下单率 | 下降 ≥ 30% |

### 5.5 F5 · 赛后复盘（人话版）【P0】

**描述**
次日 10:00 推送前一日推荐的复盘，赢输都发。

**内容结构**

**赢：**
> "昨晚那场，AI 对了。
> 曼城 2-0，让球主胜拿下。
> AI 眼光分 +1.8。"

**输：**
> "昨晚那场，AI 错了。
> 曼城 1-1，让球没赢。
> 原因：客队临时换了门将，这个信息我们赛前没拿到。
> 这属于「信息不足」，不是模型判断错。"

**归因三分类（必须标注）**

| 类型 | 判定条件 | 用户感知 |
|---|---|---|
| 信息不足 | 赛前有未获取的关键信息 | 可原谅 |
| 模型偏差 | 无新信息，概率判断本身有问题 | 需改进 |
| 随机波动 | 概率判断正确，结果落在少数侧 | 正常 |

**业务规则**
- 每月统计三类占比并公示
- 若"模型偏差"占比 > 30%，触发模型复审

**验收标准**
| 指标 | 目标 |
|---|---|
| 连败期（≥3 连败）7 日留存 | 高于无复盘对照组 ≥ 15pp |
| 复盘推送打开率 | ≥ 20% |

### 5.6 F6 · 战绩墙【P0】

**描述**
首屏顶部常驻的战绩展示。这是初级用户唯一能理解的信任机制。

**展示内容**

```
近 10 场   中 6    AI 眼光分 84
─────────────────────────────
近 30 天   推荐 71 场  命中 39  54.9%
最长连败   5 连败（10/12–10/17）
本月最差   -8.2%（查看复盘）

全部记录赛前封存，赛后自动结算
```

**业务规则**
- **连败和最差月份必须展示**，不可隐藏、不可折叠
- 数据由系统自动计算，不可人工干预
- 提供"查看封存记录"入口

**验收标准**
- 数据与后台账本 100% 一致（每日自动校验）
- 页面加载 < 1.5 秒

## 7. 数据需求

### 7.1 数据源清单（全部走付费接口）

| 数据 | 供应商类型 | 量级价格 | 优先级 |
|---|---|---|---|
| 赔率时间序列 | The Odds API / 同类聚合商 | $50–300/月 | P0 |
| 阵容与伤停 | API-Football / Sportmonks | $20–80/月 | P0 |
| 官方竞彩 SP、单关标记、停售时间 | 自有采集 | ¥0 | P0 |
| xG / 进阶数据 | FBref（免费） | ¥0 | P1 |
| 历史赔率深度 | 商业历史包 | 一次性 $1k–5k | P2 |

> 免费赔率源不可用：存在回填、修正甚至篡改历史的问题，会导致模型在真实数据上失效。

### 7.2 核心表结构

```sql
-- 比赛主表
CREATE TABLE matches (
  match_id        TEXT PRIMARY KEY,
  league          TEXT NOT NULL,
  kickoff_utc     TIMESTAMPTZ NOT NULL,
  home_team       TEXT NOT NULL,
  away_team       TEXT NOT NULL,
  official_no     TEXT,
  single_allowed  BOOLEAN,
  sale_close_utc  TIMESTAMPTZ,
  official_handicap SMALLINT
);

-- 赔率快照（只追加，永不 UPDATE）
CREATE TABLE odds_snapshots (
  match_id    TEXT REFERENCES matches,
  source      TEXT NOT NULL,
  market      TEXT NOT NULL,
  line        NUMERIC,
  price_home  NUMERIC,
  price_draw  NUMERIC,
  price_away  NUMERIC,
  captured_at TIMESTAMPTZ NOT NULL,
  PRIMARY KEY (match_id, source, market, line, captured_at)
);

-- 推荐（赛前封存）
CREATE TABLE recommendations (
  rec_id        BIGSERIAL PRIMARY KEY,
  match_id      TEXT REFERENCES matches,
  market        TEXT NOT NULL,
  selection     TEXT NOT NULL,
  prob_model    NUMERIC,
  prob_market   NUMERIC,
  edge          NUMERIC,
  confidence    TEXT,          -- A / B / C
  rationale     TEXT,
  model_version TEXT,
  sealed_at     TIMESTAMPTZ,
  payload_hash  TEXT,
  settled_at    TIMESTAMPTZ,
  result        TEXT,          -- win / lose / void
  clv           NUMERIC
);

-- 用户票单
CREATE TABLE bets (
  bet_id     BIGSERIAL PRIMARY KEY,
  user_id    TEXT NOT NULL,
  placed_at  TIMESTAMPTZ NOT NULL,
  stake      NUMERIC NOT NULL,
  legs       JSONB NOT NULL,
  settled    JSONB
);
```

### 7.3 三条数据铁律

2. 推荐赛前封存，赛后只读
3. 所有时间戳存 UTC，展示层转本地

## 8. 算法模型规格

### 8.1 模型链路

```
球队强度（xG-based，时间衰减半衰期 180 天，主场系数单独估计）
        ↓
Dixon-Coles 比分矩阵（ρ 约 -0.05 ~ -0.08）
        ↓
各玩法概率（胜平负 / 让球 / 总进球 / 比分）
        ↓
Shin 法去水得到市场公允概率
        ↓
logit 空间加权融合  P = softmax(Σ wᵢ · logit(Pᵢ))
        ↓
isotonic 校准（out-of-fold，按联赛分段）
        ↓
edge = P_model - P_market
```

### 8.2 推荐判定规则

| 条件 | 结果 |
|---|---|
| edge ≥ 2% 且 置信度 A | 推荐（可进入 F1） |
| edge ≥ 2% 且 置信度 B | 推荐（进入列表，不主推） |
| 0 < edge < 2% | 不推荐 |
| edge ≤ 0 | 进入避雷榜候选 |

**置信度定义**

| 等级 | 条件 |
|---|---|
| A | 概率区间宽度 < 4pp，且赛前信息完整，且反向论证不成立 |
| B | 满足 A 的 2 项 |
| C | 其余 |

### 8.3 评估指标（内部）

| 指标 | 用途 | 目标 |
|---|---|---|
| log loss vs 市场 | 是否真有信息增量 | 低于市场 ≥ 0.005 |
| Brier score | 概率质量 | 持续监控 |
| 校准误差 | 模型健康 | 各分桶偏差 < 3pp |
| CLV | 领先指标（50 注即可看出方向） | > +1% |
| ROI@收盘价 | 滞后指标（需 1000 注） | 不作对外承诺 |

### 8.4 强制纪律

- **禁止用开售 SP 做回测**，必须用收盘价
- 禁止用当季数据训练当季
- 禁止使用赛后确认的阵容
- 所有回测必须 walk-forward，每赛季重估一次参数

## 9. 信任系统规格

### 9.1 赛前封存

```
seal_at   = 停售前 30 分钟
payload   = { match_id, market, selection, prob_model, prob_market,
              edge, confidence, rationale, model_version }
hash      = SHA-256(payload_json + sealed_at + model_version)
```

封存后不可修改。若赛前结论发生变化（如阵容公布），生成**新版本**并保留旧版本，两个版本都公示。

### 9.2 赛后结算

- 赛后 2 小时内自动结算
- 计算 CLV：`CLV = (下注价 / 收盘公允价) - 1`
- 结果写入账本，触发 F5 复盘推送

### 9.3 公示页面

必须包含：
- 全部推荐（含亏损）
- 每条的封存哈希与时间戳
- 月度盈亏曲线
- 校准曲线
- 归因三分类占比

## 13. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| **模型无 edge** | 产品价值归零 | W1 即建立 log loss / CLV 监控；若无 edge，产品定位改为"纪律工具"，不宣称预测能力 |
| 连败导致流失 | 核心风险 | F5 归因三分类 + 连败照发 + 预算守护（降低损失感） |
| 用户归因外部化（赢了是自己，输了怪 AI） | 留存崩塌 | 强化"过程分"概念；明确"我们不保证每场对" |
| 数据源断供 | 服务中断 | 每个源至少一个备份；对齐层做抽象 |
| 合规风险 | 下架/通道关闭 | 严守 2.2 节边界；定期自查 |
| 支付通道受限 | 无法变现 | 提前测试类目；备用通道 |
| 免费用户白嫖不付费 | 收入不达预期 | 免费层只给 1 场；会员内容锁定但可见 |
| 推荐数被迫凑数 | 质量下降 | 硬性规则：无符合条件的场次就发"今晚没有值得买的比赛" |
