# 球多多移动端 · AI 助理性重构方案（Muse 感 + 清晰 + 精准）

> 目标：把「AI 预测工具」重构成「AI 足球助理」——交互、信息、功能三层都让人感觉在和一个懂球的助理相处，同时信息不堆、数字不假、每条结论可解释。
> 现状基线：Expo RN；首页已是一条对话流（722 行单文件）；4 Tab = 预测/工具/记录/我的；工具 Tab 有 8 个计算器入口；助理有 4 个入口（首页/独立页/悬浮球/比赛选择器）；人设系统（copy/风格/记忆/连败保护）已存在。
> 日期：2026-11-11

---

## 0. 现状诊断（基于代码事实）

| 问题 | 证据 | 后果 |
|---|---|---|
| **首页信息过载** | 单屏堆 AssistantBrief + FocusPanel + Hero Verdict + 其余 Verdict + Avoid + Postmortem + Unattended + LegalFooter + 聊天线程，8+ 种消息类型 | 用户不知道先看哪；"助理感"被信息墙淹没 |
| **助理身份模糊** | 4 Tab 叫"预测/工具/记录/我的"；工具 Tab 8 个计算器（抽水/赔率/仓位/回本/串关/在售/为什么不出/账本） | 像一个博彩计算器合集，不像 AI 助理 |
| **入口重复** | 助理：首页对话/`/assistant`/悬浮球/GlobalMatchPicker；"为什么不出"在工具页+首页消息+详情页；账本在工具页+记录页 | 维护成本高，用户路径混乱 |
| **AI 感只有打字动画** | 只有 AssistantTyping，没有思考步骤、来源引用、主动追问、上下文追问、记忆确认 | "假"得不够真，像静态卡片列表 |
| **精准度缺规范** | 卡片概率单点展示，无来源/时间/cutoff/置信分档；Sportmonks 接入后会再加概率对比卡 | 数字越多越乱，越容易误导 |
| **空/休息日体验单薄** | RestMessage 一段文字 | 流失点：没比赛的日子没有打开理由 |
| **单文件超限** | 首页 722 行（规范 <300） | 难改、易回归 |

**结论：底子（对话流 + 人设 + 暖白墨绿视觉）是对的，问题在"信息分层"和"助理行为"没做出来。不换皮，重排。**

## 1. "Muse 感"的定义与真假边界

### 1.1 五层感知模型（缺一层就像工具，不像助理）

| 层 | 用户感知 | 现有 | 缺口 |
|---|---|---|---|
| L1 人格 | 它有自己的名字、头像、语气、记忆 | 有人设 copy/风格/记忆 | 首页没有"它在主动说话"的连续感 |
| L2 节奏 | 每天固定时刻它先开口（简报/赛前/赛后） | 只有打开才看到 | 缺每日简报、赛前提醒、赛后复盘三条主动消息 |
| L3 对话 | 能追问、指代、延续上下文 | /chat 单轮意图路由 | 缺多轮指代（"那这场呢"）、缺追问建议 |
| L4 可解释 | 每条结论能展开看依据 | 有三闸数据但展示分散 | 缺"展开依据"、来源 chips、思考步骤 |
| L5 诚实 | 不知道就说不知道，缺数据就明说 | 部分有（fallback 文案） | 缺统一的"数据不足"视觉语言 |

### 1.2 "哪怕是假的"——真假边界

- **可以模拟（人设表演）**：说话节奏、思考动画、主动关怀、语气、追问、打字机、情绪反应；
- **不可以编造（事实）**：概率、赔率、赛果、伤停、封存哈希、命中率——必须来自真实接口；
- **模拟内容必须可识别**：开发/演示态的假数据统一打 `演示数据` 角标（一句话规则，写进组件）；生产态不允许任何假数字；
- 理由：助理一旦被抓到编数字，信任一次性归零；"表演"可以假，"事实"不能假。

## 2. 信息架构重构：4 Tab 重新分工

```text
现在：预测 | 工具 | 记录 | 我的
之后：助理 | 比赛 | 记录 | 我的
```

| Tab | 职责 | 吸收/删除 |
|---|---|---|
| **助理**（首页） | 对话流 + 今日简报 + 已发布预测消息 + 快捷意图 | 吸收 `/assistant` 独立页（保留为全屏对话模式，由首页"展开"进入）；悬浮球保留但只做"快捷提问"（3 个 chips + 输入），不重复完整对话 |
| **比赛** | 在售雷达：日期条 + 筛选 + 比赛卡 + 详情 | 吸收"今日在售"工具页；"为什么不出"并入比赛详情；GlobalMatchPicker 删除（比赛 Tab 本身就是选择器） |
| **记录** | 账本 + 周报 + 复盘 + 连败 | 吸收工具页"公开账本"入口 |
| **我的** | 人设/记忆/通知/偏好/合规 + 计算器二级页 | 接收工具页剩余计算器（抽水/赔率/仓位/回本/串关），降级为"助理技能"二级菜单，不再占 Tab |

**入口收敛表**：

| 功能 | 现在 | 之后 |
|---|---|---|
| 对话 | 首页 + /assistant + 悬浮球 | 首页（主）+ 全屏对话（次）+ 悬浮球（快捷提问） |
| 今日在售 | 工具页 | 比赛 Tab 默认列表 |
| 为什么不出 | 工具页 + 首页消息 + 详情 | 比赛详情"AI 解读"区（一处） |
| 账本 | 工具页 + 记录页 | 记录 Tab（一处） |
| 串关参谋 | 工具页 | 助理对话意图"串关"→ 卡片；详情页入口 |
| 抽水/赔率/仓位/回本 | 工具页 | 我的 → 助理技能（二级） |

## 3. 页面级方案

### 3.1 助理首页（核心，目标：3 秒看懂"今天有没有预测"）

从上到下**只允许 5 个区块**：

```text
① 身份条：头像 + “小九 · 在线” + 日期（今天/昨天切换）
② 每日简报卡（唯一大卡）：
   一句话结论（如“今晚 3 场已发布，2 场被砍，1 场数据不足”）
   + 三个小数字（已发布/被砍/数据不足）
   + 主按钮「展开今日计划」→ 展开后才出现预测卡列表
③ 精选预测消息：最多 3 条（Hero + 2），其余折叠为「还有 N 场」
④ 对话流：用户气泡 + 助理卡片（Verdict/分析/复盘/记忆确认）
⑤ 底部：输入框 + 4 个快捷意图 chips（今天看哪场 / 为什么不出 / 复盘昨天 / 我的主队）
```

- **删除**：常驻 LegalFooter（移到"我的-合规"+ 首次启动一次性展示）；Avoid/Postmortem/Unattended 三条消息合并为一张「今日没推的场次（N）」折叠卡，点进比赛 Tab 筛选；
- **休息日**：简报卡变成"今天没有竞彩场次"，下面给三选一：看昨天复盘 / 看下一场预告 / 助理小知识（真实数据，如"近 7 天联赛分布"）；
- 首页文件拆分：`AssistantHome.tsx`（壳 <150 行）+ `DailyBriefCard` / `VerdictMessage` / `ConversationThread` / `QuickIntents` / `ChatComposer`。

### 3.2 比赛 Tab（在售雷达）

- 顶部：日期条（今天/明天/后天）+ 筛选 chips（全部 / 单关 / 关注 / 联赛）；
- 列表卡（FlashList）：`联赛 · 编号` / `主队 vs 客队` / `开赛时间` / `单关` / 三闸状态点（价/市/模）/ 概率条（有模型时）；
- 点进详情：见 3.3；
- 已结束场次可切"赛果"视图（记录联动）。

### 3.3 比赛/判决详情（信息精准的样板页）

```text
① 头图：对阵 + 开赛 + 联赛 + 状态（在售/已封存/已结算）
② 概率对比卡（Sportmonks 接入后）：
   竞彩 SP 隐含 | 融合模型 | Pinnacle 基准 —— 三条横条 + 差值
   右上角：可预测性徽章（高/中/低/未知）
③ 助理解读卡：2-3 句结论 + “展开依据”
   展开后：三闸（价/市/模）逐项 + 伤停/阵容/交锋 + 数据来源与截止时间
④ 情报时间线：伤停（T-24h）、预测首发（T-2h）、确认阵容（T-30m）——只展示，不改封存
⑤ 封存信息：hash 前 12 位 + 封存时间 + “验证”入口（分享卡同款）
⑥ 底部动作：看助理分析 / 加入关注 / 分享（不出现“买/注”字样）
```

### 3.4 记录 Tab

- 顶部：本周命中率 / 连败状态 / 已结算 N 场；
- 列表：按日期的判决与赛果对照（方向、概率、结果、封存 hash）；
- 周报卡：助理口吻总结（真实数字），可分享。

### 3.5 我的

- 助理区：风格、记忆（可见可删）、通知；
- 偏好区：主队、风险偏好、年龄/合规；
- 技能区：抽水/赔率/仓位/回本/串关（二级页，低频入口）；
- 关于/反馈。

## 4. AI 助理感：12 个可落地机制

| # | 机制 | 实现要点 | 数据真假 |
|---|---|---|---|
| 1 | **每日简报** | 早 9:00 / 赛前 3h 两条本地+推送；内容=今日场次/已发布/风险一句 | 真实数字 |
| 2 | **主动追问** | 简报末尾带 1 个问题 chip（"要看被砍的原因吗？"） | 真实 |
| 3 | **思考步骤** | 发送后依次显示"查竞彩 SP… 对国际盘… 跑模型…"，每步对应真实请求阶段的文案映射（非随机） | 步骤真实，文案表演 |
| 4 | **流式输出** | 后端 `/chat` 增加 SSE；前端逐字渲染；无 SSE 时用分块打字机 | 真实 |
| 5 | **来源 chips** | 每条回答底部：`竞彩 SP · 14:27` `Sportmonks · 14:10` `模型 v2` | 真实 |
| 6 | **展开依据** | 默认折叠，展开显示三闸/概率/伤停；埋点记录展开率 | 真实 |
| 7 | **记忆确认** | "你之前说主队是曼城，要只看它吗？"（读 memories） | 真实 |
| 8 | **上下文指代** | 会话内保留 last_match；"这场/那场"解析 | 真实 |
| 9 | **场景语气** | 人设系统扩展 4 场景：赛前/赛后/连败/休息日 | 表演 |
| 10 | **失败诚实** | "数据源还没回来，我 5 分钟后再试" + 重试按钮；不假装有结论 | 真实 |
| 11 | **语音输入** | Expo 语音识别（可选，二期） | 真实 |
| 12 | **分享卡** | 助理口吻赛前卡/复盘卡，带封存 hash 可验真 | 真实 |

**关键：3/4/5 三条是"像助理"与"像列表"的分水岭，优先级最高。**

## 5. 信息精准性规范（写进组件，不靠自觉）

1. **三层信息**：结论（方向/概率/置信）→ 依据（三闸/模型/市场）→ 原始（来源/时间/cutoff）；
2. **概率必须有对照**：单点概率不展示；至少"竞彩隐含 + 模型"两条，否则显示"数据不足"，不硬凑；
3. **置信分档**：高/中/低/未知（predictability + 模型一致性 + 市场分歧），不只给数字；
4. **时间戳**：每块数据带"截至 HH:mm"；超过 15 分钟变灰 + "可能已变化"；
5. **来源徽章**：竞彩官方 / Sportmonks / 融合模型，固定位置（卡片右上）；
6. **缺口诚实**：缺阵容/缺市场时在解读里明说"缺 X，置信下降"，不用模糊话术盖过去；
7. **格式统一**：概率 1 位小数、赔率 2 位、金额千分位、时间用"今天 19:30"；
8. **合规**：不出现"买/注/推荐/稳赚/必中/价值/edge"；统一脚注"仅供参考，非投注建议"。

## 6. 视觉与动效（沿用现有 tokens，不换皮）

- 保留暖白 + 深墨绿；强调色只用于"已发布/正向"；危险色只用于"被砍/连败"；
- 助理消息：左侧小头像 + 卡片；用户消息：右侧墨绿气泡；消息间距 12/20 两级；
- 动效：入场 fade+slide 160ms；打字点；数字滚动；概率条 400ms 增长；封存 hash 打字机；全部走 Reanimated；
- Haptics：发送、收到、封存、分享四处；
- 图标全部 `react-native-svg` 线性；禁止 emoji 表达状态；
- 字体：现有 display/h1/h2/body/small；数字用等宽变体（tabular）避免跳动；
- 空状态：SVG 线性插画 + 一句人设文案 + 一个动作按钮（不留白）。

## 10. 你忽略但必须补的 12 件事

1. **首次 onboarding 的助理建立**：名字/头像/语气三选一 + 年龄确认，第一次对话由助理先开口；
2. **推送人格化但合规**：推送文案走人设，但只写"今日预测已更新"，不带赔率/结果；
3. **分享卡**：赛前卡（方向+概率+hash）与复盘卡（命中/归因），带动传播；
4. **未登录体验**：匿名可看简报与比赛，登录后才启用记忆与关注（降低首跳流失）；
5. **连败保护的情感设计**：不只是拦截弹窗，助理要主动说"今天建议只看不下"；
6. **数据延迟的视觉语言**：数据 stale 时全局一致的灰标 + 说明，不是零散提示；
7. **错误与空态**：每个页面三态（loading/empty/error）都有设计，不出现白屏；
8. **无障碍与大字模式**：动态字体下卡片不截断、按钮不重叠；
9. **平板/折叠屏**：两栏布局（列表+详情），至少不拉伸变形；
10. **反馈入口**：对话里一句"反馈"即可提交，带 session 上下文（排障用）；
11. **隐私**：分享卡与埋点不含用户身份/注单；记忆可一键清空；
12. **商业化预留**：未来会员/付费解读的位置（详情页"深度解读"卡位），现在不建付费墙但别把结构做死。

## 11. 不做清单（防过度设计）

- 不做复杂图表/仪表盘（概率条+三闸点足够）；
- 不做多助理人格切换（一个人设做深，不做多个做浅）；
- 不做社区/评论/跟单（偏离赛前预测定位，合规风险高）；
- 不做假数据演示模式进生产包（演示角标只存在于 dev）；
- 不重做视觉体系（现有暖白墨绿已成立，本轮只做层级与动效）。
