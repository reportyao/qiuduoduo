# 球多多 · AI 助理 × OPC 化重构方案（基于 Sportmonks 真实数据）

> 前提：数据源 = 自建竞彩采集器 + Sportmonks（Growth 27/30 + 4 specials，试用至 2026-11-25，之后 €197/月）。
> 真实数据约束：预测 25 种类型、历史可回溯 ≥1 年、Pinnacle 非全联赛可用、欧国联需 €129 专项、xG 仅赛后、Value Bets 稀疏。
> 目标：产品像 AI 助理，运营像 OPC——系统自动跑，人只看异常。
> 日期：2026-11-11

---

## 0. 三条设计原则

1. **助理负责解释，系统负责跑腿**：用户看到的是"助理在说话"，背后是自动化管线；你看到的是"驾驶舱 + 异常队列"，不是一堆图表。
2. **数据不足就明说**：模型未启用、市场缺失、联赛无覆盖，UI 与后台统一用同一套"缺口语言"，不硬凑、不伪装。
3. **每个自动化都有熔断**：自动发布、自动回测、自动换源，都必须有预算/质量/差异熔断，出问题自动停并通知，而不是等你发现。

## 1. 后端重构：三层 + 一张开关表

### 1.1 数据层（按 jc-data-model 落）

```text
jc_matches            竞彩主表（match_id 主键，trade_date 05:00 切日）
jc_source_links       竞彩 ↔ SM fixture 映射（confidence/method）
sm_predictions        fixture_id + type_id + payload + captured_at（冻结快照）
sm_odds               fixture_id + bookmaker_id + market_id + label + value + captured_at
sm_bookmaker_status   league_id + bookmaker_id + available + last_seen
sm_predictability     league_id + metric_type(241-245) + data + captured_at
sm_backtests          league_id + sample_n + rps_sm/rps_pin/rps_dc + ci + enabled + run_at
sm_valuebets          fixture_id + payload + captured_at（只做参考）
sm_usage              按日/端点/实体记账
sm_dead_letter        失败请求（端点/参数/错误/重试次数）
ops_jobs              定时任务运行记录（job/status/duration/error）
ops_exceptions        异常队列（severity/source/message/status/actions）
```

### 1.2 预测接入：只取需要的，别把 25 种全塞进 UI

| 用途 | 取哪些 | 说明 |
|---|---|---|
| 模型闸 | 237（1X2） | 唯一必需 |
| 详情页参考（折叠） | 235（O/U 2.5）、231（BTTS） | 可选，明确标"第三方参考" |
| 未来玩法 | 240/232/239/角球 | 先入库不展示 |
| 不展示 | 比分矩阵、单队大小球、角球 | 信息过载且易误解 |
| 不接入 | Value Bets | 稀疏（全量 3 条），C 端合规风险，仅后台参考 |
| 不买 | xG | 只有赛后，赛前无用 |

### 1.3 模型闸：按联赛开关，不由代码写死

```text
每个联赛 L 每周自动回测：
  sample≥100 且 RPS_SM < RPS_PIN（95% CI 不交叉）→ enabled
  否则若 RPS_DC < RPS_PIN → 用 DC
  否则 → 关闭模型闸（不发布，UI 标"模型未启用"）
```

- `sm_backtests.enabled` 是唯一事实源；`verdict` 证据记录 `model_source / rps_* / sample_n`；
- 五大联赛：DC 与 SM 都参与比较，按逆 RPS 加权；非五大：SM vs Pin 二选一；
- 周任务自动更新开关，变更进 `admin_audit`，不手工改权重。

### 1.4 市场闸：书商降级链（真实数据验证过）

```text
Pinnacle(20) 有 → 去水基准
否则 bet365(2) 有 → 去水基准
否则 ≥3 家可用书商中位数 → 去水
都没有 → market=pending，不发布
```

- 每联赛记 `sm_bookmaker_status`；J1 这类晚挂赔率的联赛，T-2h/T-30m 各重试一次；
- 市场闸主判据仍是"竞彩去水 vs 基准偏差 <5pp"，全庄离散只做 IQR 辅助展示。

### 1.5 OPC 自动化任务表

| 时间 | 任务 | 失败处理 |
|---|---|---|
| 每 5 分钟 | 采集器心跳检查（>35min 断流告警） | 异常入队 + 推送 |
| 06:00 | 数据巡检：SP 文件/SM 配额/订阅到期/映射率 | 异常入队 |
| 08:00 | 生成今日简报（可发布/被砍/缺口） | 失败重试 3 次 |
| 赛前 T-3h | 拉预测/赔率/伤停/阵容，跑三闸，发布 | 缺口降级，不阻塞 |
| 赛前 T-2h/T-30m | 补拉赔率、确认阵容（只进情报） | 失败记录 |
| 赛后 02:00 | 结算 + 复盘 + 数据对账 | 差异>0 告警 |
| 周一 04:00 | 周报 + 全联赛回测 + 开关建议 + 换槽建议 | 失败重试 |
| 实时 | 配额 80% 预警、发布熔断、结算差异熔断 | 自动暂停 + 推送 |

**OPC 核心：这些任务全部由 cron/systemd timer 跑，后台只展示结果和异常，不要求你点“运行”。**

## 2. 管理后台：从“功能页集合”改成“OPC 驾驶舱”

### 2.1 一屏结构（默认首页）

```text
① 今日状态条：可发布 N 场 / 暂停中 / 数据源健康灯（采集器·SM·LLM）
② 异常队列（唯一需要你动手的地方）：
   每条 = 严重度 + 一句话 + 建议动作（按钮）
   例：「采集器 48 分钟无心跳」→ [重启] [查看日志]
       「日职 3 场无赔率」→ [T-2h 重拉] [跳过该联赛]
       「结算差异 2 场」→ [对账] [暂停发布]
③ 今日流水（折叠）：已发布/被砍/数据不足，按场次列出，点开看三闸证据
④ 三个折叠区：模型联赛表 / 数据源与配额 / 内容与复核
```

### 2.2 模型联赛表（替代“手工调权重”）

| 联赛 | 样本 | SM RPS | Pin RPS | DC RPS | 开关 | 最后回测 | 建议 |
|---|---|---|---|---|---|---|---|
| 英超 | 320 | 0.190 | 0.196 | 0.191 | ✅ SM | 11-10 | 保持 |
| 西甲 | 280 | 0.143 | 0.116 | 0.138 | ❌ | 11-10 | DC 优先 |
| 日职 | 120 | 0.21 | 0.22 | — | ✅ SM | 11-10 | 观察 |
| 欧国联 | — | — | — | — | ❌ 无订阅 | — | 需 €129 专项 |

- 只读自动回测结果；开关变更只能通过“应用建议”按钮，不能手填数字；
- 每行可展开看最近 10 场预测 vs 收盘对比。

### 2.3 数据源与订阅

- 采集器：在线状态/最后心跳/SP 文件年龄/重启按钮；
- Sportmonks：套餐/到期日/剩余联赛名额（当前 3）/日调用/配额水位/各联赛书商可用性；
- 换槽建议：按竞彩近 90 天场次量 vs 当前订阅，列出“建议换入/换出”，一键跳转 Sportmonks 后台（不自动改订阅）；
- 月成本卡片：€197/月 + 单场数据成本，让 OPC 一眼知道值不值。

### 2.4 内容与复核

- 发布流水：L1-L5 结果、封存哈希、异常原因；
- 人工介入只保留两个入口：**发布前抽检**（默认自动通过）与**异常复核**（被熔断的场次）。

## 3. 前端：AI 助理体验（真实数据版）

### 3.1 首页（5 区块，不再堆消息）

```text
① 身份条：助理头像 + 在线 + 日期
② 每日简报卡：一句结论 + 三个数字（可发布/被砍/数据不足）+ 「展开今日计划」
③ 最多 3 条预测消息；其余折叠「还有 N 场」
④ 对话流 + 快捷意图（今天看哪场/为什么不出/复盘昨天/我的主队）
⑤ 输入框
```

休息日：简报变成“今天没有竞彩场次”，给三选一（昨日复盘/下一场预告/数据小知识）。

### 3.2 详情页（精准信息样板）

```text
① 对阵头图 + 状态（在售/已封存/已结算）
② 概率对比卡：
   竞彩 SP 隐含 | 模型（仅 enabled 联赛） | 市场基准（标注 Pinnacle/bet365/中位数）
   右上：模型状态徽章（已启用/未启用/数据不足）
③ 助理解读：2-3 句 + 展开依据（三闸/伤停/阵容/交锋）
④ 情报时间线：伤停 T-24h / 预测首发 T-2h / 确认阵容 T-30m（只展示，不改封存）
⑤ 封存 hash + 验证入口
⑥ 动作：看助理分析 / 关注 / 分享
```

### 3.3 真实数据下的“诚实降级”

| 情况 | UI 表现 |
|---|---|
| 联赛模型未启用（回测没跑赢市场） | 概率卡只显示“竞彩隐含 + 市场基准”，标注“该联赛模型未启用” |
| 欧国联（无订阅） | 显示“第三方数据未覆盖”，不显示概率对比 |
| Pinnacle 缺失 | 市场基准标注实际书商（bet365/中位数），不写 Pinnacle |
| 赔率未挂（日职早场） | 显示“赔率待更新”，T-2h 自动刷新 |
| 联赛/杯赛无预测（如远期英联杯） | 只显示 SP 与“数据不足”，不生成 AI 解读 |

### 3.4 助理话术库（与数据状态绑定）

- 模型启用且过闸：“三关都过，方向与概率如下”；
- 模型未启用：“这个联赛的模型还没跑赢市场，我只给你竞彩价和市场基准”；
- 数据缺口：“缺赔率/缺阵容，我先不下结论”；
- 被砍：“价/市/模哪一关没过，点开看”；
- 绝不出现“稳赚/必中/价值/edge”。

## 4. OPC 运营指标（验收）

| 指标 | 目标 |
|---|---|
| 每日人工操作时间 | <10 分钟 |
| 异常发现→处理 | <30 分钟（推送 + 一键动作） |
| 发布自动化率 | >90% 场次无需人工 |
| 结算差异 | 0 未解释 |
| 数据缺口场次占比 | 可见、可解释，不静默 |
| 单场数据成本 | 后台可见，月度复盘 |

## 5. 落地顺序（与门制对齐）

| 阶段 | 内容 | 依赖 |
|---|---|---|
| **P1 后台驾驶舱**（3 天） | 今日状态条、异常队列、模型联赛表（先接回测 CSV）、订阅/配额卡 | 无（数据已有） |
| **P2 后端自动化**（4 天） | sm_* 表 + 同步器 + 回测 job + 开关表 + 熔断 | 新订阅已生效 |
| **P3 前端助理化**（4 天） | 首页 5 区块、详情概率卡、诚实降级、话术库 | P2 数据 |
| **P4 闭环**（持续） | 周报自动生成、换槽建议、成本复盘、A/B | P1-P3 |

## 6. 不做清单

- 不把 25 种预测全展示（只 1X2 + 可选 2 项）；
- 不做手工权重编辑（只“应用建议”）；
- 不做 Value Bets C 端功能；
- 不做 xG 赛前展示（没有赛前数据）；
- 不做多助理人格/社区/跟单；
- 不在后台堆图表，只保留“状态 + 异常 + 建议动作”。
