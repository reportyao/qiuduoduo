范围：`b5149e2` 自建 PostgreSQL 架构（连接池、索引、迁移、保留策略、部署、健康检查、文档）及其后续审查修复。目标仍是“生产 Postgres + SQLite 仅测试/旧部署回退”。

## 审查后修复

1. **保留策略状态值错误**：`db_maint` 删通知时等的是 `"skipped"`，实际状态是 `"suppressed"`，导致被抑制推送永久不清理。plan/apply 统一改为 `sent/failed/suppressed`。
2. **过期未扇出事件不回收**：原条件只删 `fanout_at IS NOT NULL` 的 events，worker 失败留下的过期事件会永久堆积。新增 `expires_at < NOW` 条件，同时保留“未扇出且未过期”的在途事件。
3. **大事务删除**：保留策略由一次 `DELETE` 改为按主键 1000 行一批、每批提交；新增“选到行但删除 0 行”保护，避免条件写错时无限循环。
4. **event_id 复用污染通知去重**：notifications 保留 180 天、events 只保留 90 天且无外键；SQLite `INTEGER PRIMARY KEY` 删除最高行后会复用 ID，旧通知可能让新事件被误判“已通知”。事件删除增加 `NOT EXISTS (notification.event_id = event.id)`，引用清掉后才回收。
5. **生产 Postgres 启动期 DDL**：`init_db()` 原来在 Postgres 上仍执行 `create_all` + `ALTER`，与“schema 只由 Alembic 管”冲突，多 worker 还可能并发抢 DDL 锁。Postgres 方言直接返回；由部署阶段 `alembic upgrade head` 负责。
6. **旧 SQLite 索引不生效**：`create_all(checkfirst=True)` 不会给已存在表补新索引，部署默认仍是 SQLite 时热路径索引实际不存在。`init_db()` 在旧库上增加 `_ensure_indexes()`；新库仍由 `create_all` 一次建全。
7. **Alembic 连接配置**：改为 `NullPool` + `application_name=jieqiu-migrate`；迁移 `statement_timeout=0`（大表建索引不被 API 的 15s 打断），保留 `lock_timeout=5s`。
8. **健康检查探针过重**：`/health` 默认只做 DB ping + 延迟 + 后端名，`?detailed=1` 才跑全表 COUNT；补契约测试。
9. **部署退出码被管道吞掉**：`pip ... | tail`、`alembic ... | tail` 返回的是 `tail` 状态，迁移/依赖失败会继续部署。改为写日志后显式 `exit $rc`；seed 同样校验。
10. **部署保护失效**：多处用 `assert`，`python -O` 下会被编译掉。统一改为 `SystemExit`；新增代码解包、cron、systemd、服务 active、`/health` 校验。
11. **部署凭据硬编码**：移除 SSH/控制台明文密码，改为 `JQ_DEPLOY_PASSWORD`/`JQ_CONSOLE_PASSWORD`；数据库 URL、控制台密码、JWT 密钥写入 `/etc/jieqiu-backend.env`（root:root 0600），unit 只引用 `EnvironmentFile`；服务改为 `User=ubuntu`。
12. **sudo 密码泄露**：原来 `echo '密码' | sudo -S` 会把密码放进远端 shell 命令行，`ps` 可见。改为 Paramiko stdin 写入。
13. **cron 注入/展开**：cron 内容由 SFTP 写入而不是 `echo "..."`，避免密码里的 `$`/反引号被 shell 展开；数据库 URL 统一 shell quote。
14. **SQLite 默认 URL 斜杠错误**：`sqlite:////{DATA}` 拼出 5 个斜杠，实际 database 是 `//home/...`；修正为 `sqlite:///{DATA}`，并兼容 `postgres://` → `postgresql://`。
15. **索引顺序**：新增 `ix_verdicts_trade_kickoff (trade_date, kickoff)` 服务公开账本；`ix_verdicts_status_settled_kickoff` 调整为 `(status, kickoff, settled)` 服务结算/复盘。
16. **备份文档诚实化**：明确当前只给命令、未自动化 pg_dump/PITR；写明这是上线阻塞项，避免把文档当成已运行任务；补充部分唯一索引上线前的重复数据检查。
17. **回滚清理**：`get_db()` 的 rollback 加异常保护，连接已断时不会用清理异常覆盖原始错误。

## 未在本机执行 / 残余风险

- **没有真实 PostgreSQL 实例**：本机无 Docker/psql，未做真实连接、锁等待、`EXPLAIN (ANALYZE, BUFFERS)`、备份恢复与 PITR 验证；只验证了离线 DDL 与 postgres 方言编译。
- 未实际执行 `deploy.py`：远端 systemd/cron/EnvironmentFile 行为只做了代码级校验，首次部署需按 README 导出密码并观察。
- **备份/PITR 仍未自动化**：pg_dump 与 WAL 归档需要上线前配置；当前文档已明确标注。
- **生产默认仍是 SQLite**：未设置 `JQ_PROD_DATABASE_URL` 前，线上仍是旧 SQLite（现在会补建索引），规模/并发上限受 SQLite 限制；切 Postgres 仍需执行迁移导入与回滚演练。
- 大表加索引仍是普通 `CREATE INDEX`，未使用 `CONCURRENTLY`；首次迁移是空库/小表可接受，后续大表变更必须按文档单独评审。
- 部署仍使用 SSH 密码 + `AutoAddPolicy`；生产建议改为密钥登录并固定 known_hosts/主机指纹。
- 未做多 worker 并发启动、连接池耗尽、慢查询压测；连接数上限按文档估算，需上线后看 `pg_stat_activity`。
