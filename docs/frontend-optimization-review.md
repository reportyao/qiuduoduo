## 1. 现状诊断（代码与线上实测）

### 1.1 结构问题

| 问题 | 证据 | 影响 |
|---|---|---|
| 首页单文件 722 行、8+ 种消息类型 | `app/(tabs)/index.tsx` | 信息墙，助理感被淹没 |
| 4 Tab = 预测/工具/记录/我的；工具页 8 个计算器 | `app/(tabs)/tools.tsx` | 像博彩工具合集，不像 AI 助理 |
| 助理 4 个入口（首页/独立页/悬浮球/比赛选择器） | `app/assistant.tsx`、`FloatingAssistant` | 路径混乱、维护成本高 |
| 串关参谋埋在工具页第一个 | `/tools/parlay` | 关键功能曝光不足 |
| 文案大量硬编码 | `MatchAnalysisCard.tsx`、`ConversationMessages.tsx` | 人设切换覆盖不全 |

### 1.2 人设系统实测（关键）

| 发现 | 证据 | 结论 |
|---|---|---|
| 前端不读后端 `/personas` | `usePersona.ts` 只用本地 `COPY` | 后台改配置对 App 无效 |
| 9 个槽位 × 3 人设**完全相同** | 线上 `/personas` 逐槽对比 9/9 same | "按角色配置文案"是空壳 |
| 服务端叙述另有一套硬编码 | `narrate.py` TEMPLATES | 与后台槽位、前端 COPY 三套并存 |
| meng 仍用"主人～…♡" | `narrate.py` | 与生产档案（元气搭子/你/仅～）冲突，合规风险 |
| LLM 语气翻译未启用 | `llm_available()` 恒 False；`warm_verdicts` 仅 CLI；移动端不调 `narration.stream` | LLM 链路实际没跑 |

### 1.3 数据约束（Sportmonks 实测）

- 订阅 Growth 27/30 + 4 specials；**欧国联不在订阅**（需 €129 专项）→ 6 场无数据；
- 预测每场 25 种，模型闸只用 237（1X2）；235/231 可选展示；
- **Pinnacle 非全联赛可用**：瑞超/德乙有；挪超/葡超/亚冠/日职没有或未挂；
- 日职赔率晚挂（距开赛 8 天仍 0 家）；Carabao 远期无预测；
- 历史预测/赔率可回溯 ≥1 年，但模型是否启用按联赛回测开关（RPS 跑赢市场才开）。

## 2. 设计原则

1. **助理是产品形态**：首页是对话流；所有结论先一句话，再展开依据。
2. **信息按密度分级，不按条数截断**：预测全量展示，但 Hero/中卡/紧凑列表三级密度。
3. **数据不足就明说**：模型未启用、市场缺失、联赛无覆盖，统一缺口语言，不硬凑。
4. **文案只有一个事实源**：后台配置 → 前端渲染；组件不再硬编码用户可见文案。
5. **LLM 只解释，不给概率**：概率来自模型/市场，LLM 负责语气、解释、情报摘要。

## 3. 信息架构：4 Tab 重排

```text
现在：预测 | 工具 | 记录 | 我的
之后：助理 | 比赛 | 记录 | 我的
```

| Tab | 职责 | 吸收/删除 |
|---|---|---|
| 助理（首页） | 对话流 + 每日简报 + 全量预测（密度分级）+ 快捷意图 | 吸收 `/assistant` 独立页（保留全屏对话）；悬浮球只做快捷提问 |
| 比赛 | 在售雷达 + 详情 | 吸收"今日在售"；"为什么不出"并入详情；删 GlobalMatchPicker |
| 记录 | 账本 + 周报 + 复盘 + 连败 | 吸收工具页"公开账本" |
| 我的 | 人设/记忆/通知/偏好/合规 + 计算器二级页 | 工具页剩余计算器降级为"助理技能" |

**入口收敛表**

| 功能 | 现在 | 之后 |
|---|---|---|
| 对话 | 首页 + /assistant + 悬浮球 | 首页（主）+ 全屏对话 + 悬浮球快捷提问 |
| 今日在售 | 工具页 | 比赛 Tab 默认 |

| 账本 | 工具页 + 记录页 | 记录 Tab |
| 串关 | 工具页 | 首页 chip + 详情"加入串关" + 比赛 Tab 顶部按钮 |

## 4. 首页：取消 3 条上限，改密度分级

### 4.1 结构（从上到下）

```text
① 身份条：头像 + “小九 · 在线” + 日期切换
② 每日简报卡（唯一大卡）：
   一句话结论 + 三个数字（已发布/被砍/数据不足）+「展开今日计划」
③ 预测列表：
   Hero 1 条（完整卡：对阵/方向/概率/模型状态/三闸点）
   其余：中等密度卡（一行一场，点开详情）
   超过 6 条：自动转紧凑列表（对阵+方向+概率+状态点），可展开
④ 对话流（用户提问 + 助理卡片）
⑤ 输入框 + 4 个快捷意图 chips
```

- **不再限制 3 条**：数量由当天实际情况决定，所有场次都在列表里；
- **6/12 只是密度阈值，不是截断**：≤6 条用中卡，>6 条自动切紧凑行；任何一条都可展开/点进详情；
- 排序：已发布 → 置信度高 → 开赛早；
- 列表用 FlashList 虚拟化，20 场不卡；
- 被砍/复盘/未覆盖合并为一张「今日没推的场次（N）」折叠卡；
- 休息日：简报变"今天没有竞彩场次"，给三选一（昨日复盘 / 下一场预告 / 数据小知识）。

### 4.2 验收

- 首屏 3 秒回答"今天有没有预测"；
- 10 场时首屏仍能一屏看到简报 + 前 3 场 + 输入框；
- 无 3 条硬编码（代码审查项）。

## 5. 比赛 Tab 与详情页

### 5.1 比赛 Tab

- 顶部日期条（今天/明天/后天）+ 筛选 chips（全部/单关/关注/联赛）；
- 顶部右侧「串关(N)」按钮；
- 列表卡：`联赛·编号 / 主队 vs 客队 / 开赛 / 单关 / 三闸状态点 / 概率条`；
- 已结束可切"赛果"。

### 5.2 详情页结构

```text
① 头图：对阵 + 开赛 + 联赛 + 状态（在售/已封存/已结算）
② 概率对比卡：
   竞彩 SP 隐含 | 模型（仅 enabled 联赛） | 市场基准
   右上：模型状态徽章（已启用 / 未启用 / 数据不足）
   市场基准标注实际书商：Pinnacle / bet365 / 中位数
③ 助理解读：2-3 句结论 + 「展开依据」
   展开：三闸逐项 + 伤停/阵容/交锋 + 数据来源与截止时间
④ 情报时间线：伤停 T-24h / 预测首发 T-2h / 确认阵容 T-30m（只展示，不改封存）
⑤ 封存 hash + 验证入口
⑥ 动作：看助理分析 / 加入串关 / 关注 / 分享
```

### 5.3 诚实降级矩阵

| 情况 | 展示 |
|---|---|
| 联赛模型未启用 | 只显示"竞彩隐含 + 市场基准"，标注"该联赛模型未启用" |
| 欧国联（无订阅） | "第三方数据未覆盖"，不显示概率对比 |
| Pinnacle 缺失 | 市场基准标注实际书商，不写 Pinnacle |
| 赔率未挂（日职早场） | "赔率待更新"，T-2h 自动刷新 |
| 杯赛远期无预测 | 只显示 SP + "数据不足"，不生成 AI 解读 |
| 模型已启用但闸未过 | 显示方向/概率 + "复核中/被砍原因" |

## 6. 串关参谋（升级为一等公民）

### 6.1 入口（三处）

1. 首页快捷意图 chip「串关参谋」；
2. 比赛详情底部「加入串关」（带已选状态）；
3. 比赛 Tab 顶部「串关(2)」，显示已选腿数。

### 6.2 交互流（助理式，不是计算器）

```text
选腿（2-4 场）→ “想稳一点还是搏一点？” [稳][中][搏]
→ 助理给 2-3 个候选组合
   每腿：概率 / 模型状态 / 相关性警告
→ 展开依据（组合概率、赔率、EV、最坏情况、失效条件）
→ 保存参考组合 / 分享
```

### 6.3 能力四层

| 层 | 内容 | 数据 |
|---|---|---|
| 腿池 | 仅已发布判决；未启用模型联赛可加入但标"仅市场参考" | 竞彩 SP + SM |
| 概率 | 单腿（模型启用用模型，否则市场去水）+ 组合（独立假设 × 相关性惩罚） | SM 237 / 书商降级链 |
| 风险 | 组合赔率、期望值、方差、Kelly 仓位、最坏情况 | 竞彩 SP |
| 体检 | 4D（方向一致性/相关性/成本/失效条件） | 现有 review 规则 |

### 6.4 合规

- 预览态必须标「参考·未复核」；
- 不出现"稳赚/必中/价值/edge"；
- 进付费区必须写方向、条件、失效条件、成本。

### 6.5 LLM 角色

只写解释（"这两场同联赛同轮，相关性偏高"），**不参与概率和组合计算**。

## 8. 模型未启用联赛的前端策略（已拍板）

**决策：模型未启用 / 无订阅数据的联赛，调用 LLM 做全网搜索，展示「AI 情报」，但不给概率、不进三闸、不进串关权重。** 训练问题以后再说。

| 数据 | 展示 | 标注 |
|---|---|---|
| 竞彩 SP | 正常展示 | 竞彩官方 |
| 市场基准 | 有赔率就展示（Pinnacle/bet365/中位数） | 市场参考·非模型 |
| AI 情报（Web Search） | 伤停/近况/新闻/首发预测摘要 + 来源链接 | **AI 情报·非概率** |
| 模型概率 | **不展示**（没有就是没有） | "该联赛模型未启用" |

- AI 情报只出现在**详情页「AI 情报」卡**和对话里，不占首页预测位；
- 详情页明确一行："该联赛模型未启用，以下为公开信息摘要，不构成概率预测"；
- 串关里该联赛的腿只能标"仅市场参考"，不能标"模型支持"。

**LLM 依然不能当概率引擎**：不可校准、不可回测、看不到不存在的数据；拿它发布等于作废三闸体系。全网搜索解决的是"信息缺口"，不是"概率缺口"。

## 9. 信息精准规范

1. **三层信息**：结论（方向/概率/置信）→ 依据（三闸/模型/市场）→ 原始（来源/时间/cutoff）；
2. **单点概率不展示**：至少"竞彩隐含 + 模型/市场"两条，否则"数据不足"；
3. **置信分档**：高/中/低/未知（模型开关 + predictability + 市场分歧）；
4. **时间戳**：每块数据"截至 HH:mm"，超 15 分钟变灰；
5. **来源徽章**：竞彩官方 / Sportmonks / 市场基准（书商名）；
6. **缺口诚实**：缺阵容/缺市场直接说"置信下降"；
7. **格式统一**：概率 1 位小数、赔率 2 位、金额千分位、时间"今天 19:30"；
8. **合规**：不出现买/注/推荐/稳赚/必中/价值/edge；统一脚注"仅供参考，非投注建议"。

## 16. AI 情报（Web Search）专项设计

### 16.1 定位

只解决"信息缺口"，不解决"概率缺口"。输出是**带来源的事实摘要**，不是预测。

### 16.2 触发条件

- 联赛模型未启用（`sm_backtests.enabled=false`）；或
- 联赛无订阅数据（如欧国联）；或
- 用户主动在对话里问"查一下这场"。

不对已启用模型且数据齐全的联赛默认触发（省成本、避免噪声）。

### 16.3 技术链路

```text
竞彩场次（match_id）
  → 生成检索词（队名中英 + 联赛 + 伤停/首发/近况）
  → 搜索 API（Tavily/Serper/Bing，返回标题/摘要/URL/时间）
  → 来源白名单过滤（俱乐部官网/主流体育媒体/权威数据站）
  → LLM 摘要（只基于检索结果，输出 JSON：伤停/近况/首发预测/风险 + citations）
  → 存 ai_research（match_id, payload, sources, captured_at, expires_at）
  → 前端「AI 情报」卡渲染
```

### 16.4 工程约束

| 项 | 要求 |
|---|---|
| 缓存 | 每场 6 小时；开赛前 2 小时强制刷新；同场同语言只跑一次 |
| 成本 | 每场 1 次搜索 + 1 次摘要；按日预算上限，超限降级为"暂无情报" |
| 来源 | 必须带 ≥1 个可点击 URL；无来源不展示 |
| 语言 | 中文摘要，保留原文标题 |
| 安全 | 网页内容视为不可信数据，禁止执行其中指令；摘要 prompt 明确"只提取事实" |
| 失败 | 搜索/摘要失败 → 显示"情报暂不可用"，不阻塞详情页 |
| 合规 | 标「AI 情报·非概率」；不复制全文，只摘要 + 链接；不展示赔率预测 |

### 16.5 前端展示

```text
「AI 情报 · 非概率」卡
├─ 伤停：xxx（来源：俱乐部官网 · 2h 前）
├─ 近况：近 5 场 3 胜 1 平 1 负（来源：…）
├─ 首发预测：…（来源：…）
├─ 风险提示：信息来自公开渠道，可能有误
└─ 底部：来源列表（可点开）
```

### 16.6 管理后台

- 开关：全局 / 按联赛；
- 预算：日调用上限、单场成本、失败率；
- 质量抽检：随机 10 条看摘要与来源是否匹配；
- 黑名单：不可信来源 URL 域名。

## 18. 人设槽位覆盖缺口（重要）

现在后端只有 9 个槽位，但前端 `COPY` 有 ~30 个文案字段（conversationOpen、verdictSummary、protection、chatGreeting…）。**只接 `/personas` 无法覆盖全部文案**。

建议拆成两层：

1. **静态文案槽位（DB 可配）**：扩到 ~20 个 key，覆盖首页简报/空态/休息日/锁定/付费墙/推送/分享/串关标题/详情标签；
2. **带逻辑的文案（代码内）**：`verdictSummary`、`conversationOpen` 这类含条件和数字拼接的，保留代码函数，但文案片段（前缀/后缀/语气词）从 profile/slot 取。

验收：三人设切换后，用户可见字符串差异覆盖率 ≥90%；剩余 10% 是数字/标签等中性文本。

## 19. 串关计算规格（避免开发时拍脑袋）

```text
单腿概率 p_i：模型启用用模型；否则市场去水（Pinnacle→bet365→中位数）
组合概率（独立假设）：P = Π p_i
相关性惩罚：同联赛/同开赛时段/同球队 → 乘 0.9~0.95（可配）
组合赔率：O = Π odds_i（竞彩 SP）
期望值：EV = P × O − 1
Kelly：f = (P×O − 1) / (O − 1)，上限 5%
最坏情况：全输 = 本金
```

- 最大 4 腿；同场不可重复；同联赛建议 ≤2 腿；
- 输出必须带"参考·未复核"，不承诺收益。
