# 运营工作台（2026-11-06）

传统后台是按数据表分页；工作台按**一条内容从采集到前端的真实路径**展示。目标是让运营
一眼看到“哪一环卡住、证据是什么、下一步做什么”，而不是在模型池、数据源、推荐主链之间猜。

入口：`/admin` →「工作台」。登录后默认进入。

## 1. 链路与名词

| 阶段 | 回答的问题 | 说明 |
|---|---|---|
| 采集 | 今天有没有拿到官方 SP？ | 家宽采集器每 5 分钟抓体彩官方赔率；每 30 分钟 SFTP 推 `sp_data.db`。服务器不能直连体彩（WAF 567）。 |
| 入库 | 采集数据有没有进后端？ | `seed` 每 30 分钟把场次、SP 快照写入后端。 |
| 市场数据 | 国际盘和阵容够不够？ | 市闸需要竞彩官方 + 至少一条国际盘；API-Football 补阵容/伤停/积分榜。 |
| 模型 | 模型有没有算出概率？ | 确定性统计模型；LLM 不参与概率。 |
| 三闸 | 价 / 市 / 模分别卡在哪？ | **价闸**=抽水是否过高；**市闸**=竞彩官方与国际盘是否对得上；**模闸**=模型覆盖是否足够。三闸全过只是 `promoted`。 |
| 封存 | 判决有没有写入链？ | 哈希链，事后可复算；封存不等于发布。 |
| 复核 | AI 复核有没有跑/降级？ | L1–L5 规则 + 可选 LLM；复核通过才允许发布。 |
| 发布 | 前端今天能看到几条？ | 只有 `published` 才进「今日预测」；`promoted` 不是已发布。 |
| LLM | 对话/复核/解读可用吗？ | fast 服务 `/chat`；deep 服务发布复核/单场解读；在「接入中心」配置。 |
| 推送 | 设备推送有没有绑定？ | JPush；不是发布的前置条件。 |

完整定义也内嵌在工作台底部「名词解释」，不用记文档。

## 2. 状态语义

- **正常**：该环节当前没有阻塞证据。
- **需关注**：能继续，但覆盖率/时延/降级有风险。
- **卡住**：该环节是当前主链的主要阻塞点；工作台会给出 `next` 动作。
- 顶部标题永远来自确定性快照，不由 LLM 生成，避免模型误报卡点。

## 3. AI 体检

「AI 体检」调用工作台诊断：

1. 后端把链路快照压缩后交给 fast LLM（TokenRhythm `qwen3.8-flash`）；
2. 模型输出 root causes、建议动作、需要人工处理的事项；
3. 模型输出不完整/超时/不可用时，自动用**规则诊断**补齐最先阻塞环节，不会空手返回；
4. 所有动作 ID 经过 allowlist，模型不能执行任意命令。

可用动作：

| 动作 | 说明 | 安全 |
|---|---|---|
| `restart_collector` | 下发采集器重启（下一次心跳退出，watchdog 拉起） | 是 |
| `sync_odds` | 只同步竞彩目标场次的国际盘，消耗 Odds API 额度 | 否，需确认 |
| `test_llm` | 测试 fast/deep 连接 | 是 |
| `run_pipeline` | build→review→publish，会改变前端内容 | 否，需确认 |

「执行安全项」只执行 `safe=true` 的动作；涉及发布或额度的动作必须人工确认。解决不了的
事项会显示在「需要你处理」。

## 4. 实现边界

- 工作台只读聚合，不改业务表；动作单独审计（`admin_audit`）。
- 采集器状态来自心跳，不依赖服务器猜家庭机器进程。
- 当前单场 AI 解读仍是同步生成 + 缓存，不是异步 job；工作台会显示今日解读数量。
- 国际盘按竞彩目标场次请求；未被 Odds API 覆盖的联赛会明确显示缺口，不硬凑。
